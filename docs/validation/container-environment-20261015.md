# 容器单一环境配置验证

日期：2026-10-15，上海时区。对应 US8、需-022、成-014、T119—T121。本次先补规格、设计和任务，再以转换与真实命令行测试驱动实现，未修改评审者维护的质量清单。

镜像仓库部署现在只维护 `.env`；程序入口显式转换允许的配置变量，复用既有类型和业务校验，在 `/tmp` 临时挂载生成独立 `0600` JSON 后启动普通服务。凭据仍使用独立秘密文件；不采用系统代理环境、不允许覆盖固定容器路径。JSON 文件模式及显式管理命令保持兼容。修改 `.env` 需用 `docker compose up -d` 重新创建容器，不能用 restart 加载新环境。

- 五项新增 Rust 测试覆盖默认、国家/时区/数值/地址转换、无关变量隔离、非法参数与真实无网络命令行。先执行因缺少转换入口失败，实现后通过。
- 格式及全部目标严格静态检查通过。普通 Rust 测试 393 项通过、37 项目标或特权用例忽略；Python 回归运行 212 项、4 项按环境跳过。
- 两种专用策略组合的实际编排输出核对：没有 build、没有用户 JSON 挂载，仅保留缓存卷、秘密文件、回环发布、只读根目录和原能力约束；国家及时区值正确传入。

- 真实镜像在无网络、无能力、只读根目录下生成合法配置；非法时区、国家列表、布尔和数字均在默认入口返回 2；合法配置经过生成及凭据读取后，在缺少能力预检处按预期阻断，没有创建网络资源。
