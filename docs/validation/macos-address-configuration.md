# 苹果接口地址配置组件

日期：2026-10-12，中国标准时间。对应 T082，属于 T057 的细分实现；不收口完整苹果后端。

已实现 `src/platform/address.rs` 的地址配置入口，只接受已认证管理会话交付且仍持有真实控制句柄的材料。调用前检查真实与有效管理员身份；进程内互斥锁串行化配置，不执行网卡命令或派生配置子进程。同步系统调用期间借用材料，不存在异步任务取消后配置子进程继续运行的问题。每个配置步骤前及最终核验后检查同一撤销令牌与真实句柄身份。

## 配置与拒绝行为

1. 从内核读取接口清单，核对本次名称、非零索引、点对点且非回环标志，要求尚无四版地址。
2. 本地地址、虚拟对端或子网范围与外部接口的地址范围或点对点目的地址冲突时拒绝；外部掩码缺失或不连续也拒绝。该检查针对接口地址，尚不替代完整路由清单检查。
3. 同地址并存仅允许调用方提供仍存活、未撤销且真实句柄再核验通过的其他项目材料；核对其名称、索引、启用标志及唯一地址、对端与掩码。并存材料最多三十二项，重复索引或不符状态拒绝；不能仅凭接口名称授权豁免。
4. 设置最大传输单元，添加唯一地址，保留原标志并启用接口。点对点采用通知中的虚拟对端与全一掩码；子网采用本地地址作为苹果点对点目的地址与通知中的掩码，不将承载远端当作虚拟对端。
5. 再读取内核清单与最大传输单元，要求身份、唯一地址、目的地址、掩码及启用标志全部一致；最后再次核对撤销与句柄身份后返回。

任何错误均撤销目标材料所属会话。函数借用材料，失败不会提前释放调用方仍持有的句柄，不会按名称删除未知接口或尝试覆盖式回滚。中途失败可能留下本次接口的部分配置；调用方必须先停止并回收隧道与业务消费者，再释放最后句柄，且不得重用已撤销材料。

## 系统调用边界

私有 `src/platform/address/sys.rs` 只封装四种固定网络控制请求：读取/设置最大传输单元、添加地址及设置标志；不接受外部请求编号、原始指针或任意命令。请求名称有界并以零终止，地址使用网络字节顺序。

现有系统依赖未提供这些操作的安全封装，因此仅在该私有模块局部允许必要的外部函数调用与联合体读取；项目其余代码继续保持拒绝不安全代码的检查。每处调用说明存储布局、初始化、请求类型和生命周期依据。回归通过本机系统头文件编译独立小程序，核对两种请求结构大小、三个地址字段偏移及四个请求编号；另有真实回环接口只读查询。没有修改全局检查规则或新增依赖。

设计依据为本机开发套件头文件，以及苹果公开的[网络配置请求定义与使用](https://github.com/apple-oss-distributions/network_cmds/blob/main/ifconfig.tproj/af_inet.c)和[内核地址处理](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/netinet/in.c)。固定隧道源码 `tun.c` 的苹果分支也区分虚拟点对点与子网配置。本组件独立实现请求封装，未复制上述实现代码。

## 本轮验证

先运行有效配置回归，在配置驱动尚未实现时失败；完成实现后通过。本轮新增十一项单元测试：

- 两种拓扑的准确配置材料与配置顺序；已有地址、错误接口及不符标志拒绝。
- 外部网络重叠、外部点对点目的地址及异常掩码拒绝；只有核验通过的项目并存材料可允许同地址。
- 六个核验边界的撤销，以及三个写入步骤的故障，均停止后续操作；配置后不一致不得成功。
- 本机真实接口清单与回环最大传输单元只读查询。
- 系统头文件的结构布局、字段偏移与请求编号核对，以及名称边界和字节顺序。
- 公开入口的普通用户拒绝、会话撤销及调用方持有资源保留，材料最后丢弃后才关闭资源。

其中配置成功、步骤故障及并存冲突用受控后端验证；普通套接字资源测试不冒充真实隧道句柄成功。原生系统调用仅执行了只读查询，没有写入真实接口。

完整普通回归：112 项单元测试、63 项普通契约测试通过。默认明确忽略三项依赖单元、三项特权契约及二十九项集成测试，共三十五项，不计入通过。格式、全目标严格静态检查及锁定构建通过。本轮未重复执行此前固定依赖或脚本检查，历史证据见[拓扑材料记录](macos-topology-material.md)。

## 尚未验收的范围

本轮免交互管理员检查仍要求密码，因此未创建接口或执行地址写入；没有将旧动态实验程序的原生报告移作本组件或新静态依赖的通过证据。三十分钟测试继续暂缓。

地址配置尚未接入正式父进程及完整管理材料流程；生产通知参数仍未启用。接口地址操作可能使内核产生隐式路由，本轮没有证明其宿主影响、同地址多隧道的原生路由归属或完整回收。子网作用域路由、公网路由、管理与业务隔离、正式低权限工作进程接入以及完整监督故障和重启仍须实现或原生验收。

下一阶段需将通知参数、严格管理入口、配置及句柄交接作为同一条受监督启动流程接通，并补齐路由前置检查、隐式路由影响与失败回收的原生证据。配置成功仍不能发布活动出口。
