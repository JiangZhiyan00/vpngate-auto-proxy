# 苹果低权限来源与候选协调

日期：2026-10-13，中国标准时间。T096 完成来源、缓存、轮次和现有私有控制协议的协调组件；真实控制子进程启动、公开网关及实例管理接入尚未完成。

## 身份与配置

正式协调入口先核对指定已有账户、实际和有效用户/组、无额外附属组，再检查配置、实例标识及初始无活动引用，之后才允许访问缓存或请求来源。配置复用共用校验，并拒绝相对数据/运行路径、候选并发大于 32、整体重试大于 32、隧道启动预算大于 120 秒及超限检测参数；不静默裁剪。部署方仍须提供已核验控制子进程和私有通道；此库入口不派生进程或绑定公开监听。

生产来源请求复用既有有界直接获取和净化器，缓存读取不刷新抓取时间，来源失败保留旧快照及时间。历史诊断只读取观察，不注入当前可用排序；过期来源和成功历史都不能恢复可用性。新来源按节点存在性和配置摘要取消过时的在途候选，保持健康活动出口；来源刷新和节点恢复使用独立退避，相同有效来源不绕过节点退避。

## 候选与活动

复用有界去重、公平轮转和恢复优先排序，恢复时逐个验证以保持优先级；成功提升活动出口后，同一轮剩余队列按候选并发继续，不重新选择或扩大该轮配额。首次恢复模式未切换会限制剩余候选为逐个执行，此行为已用受控回归复现并修正；共享调度器新增转换仅在苹果构建编译，不改变本次已固定的 Linux 被测程序。

端口层、隧道层和出口层分别记录：流式承载在低权限协调方进行有界端口连接；数据报承载标为不适用，不伪造端口成功。隧道由固定特权侧代际启动，等待就绪后才开始独立出口检测。配置与退休共用串行锁，避免退休时仍有其他候选进行并存配置；检测本身可以并行。

候选成功但仍有健康活动时退休候选，只记录短期结果，不主动轮换。待启用代际只有来源仍有效、配置仍相同、未取消且特权侧再次接受提升时，才发布本地活动引用。活动引用绑定控制连接撤销令牌；控制连接故障会同时撤销克隆和已交付引用。活动及空闲控制存活检查独立于来源刷新，状态同时关联工作和代际。

活动结构失效时先撤销本地引用，移除旧出口可用结果并记录结构失败，再退休和开启恢复；旧健康成功不能重新成为当前可用证据。恢复候选仍须重新验证，不能直接采用历史诊断。状态同步无公开异步推送；根工作代际已直接阻断业务，但本地健康状态查询仍可能受正在完成的串行控制请求影响，不据组件测试声称完整生产故障时限通过。

## 时间与停止

控制协议的成功/失败检测结果携带特权侧实际完成时间。协调方核对时间顺序，以实际完成时间计算缓存有效期，不以晚取走结果的时间延长可用性。特权侧提升继续使用原有单调时钟短期凭据，墙上时间及缓存不能伪造提升权限。

取消单个候选时不丢弃正在收发的控制请求，待请求结束后退休所属代际，防止关闭整个连接而影响健康活动。全局停止则立即撤销本地引用、清除就绪状态并主动关闭所有控制克隆；在途和排队请求结束，特权侧仍负责全部所属回收。来源任务可以取消，本地候选任务不直接中止，协调方等待它们结束。取消协调等待也会同步撤销引用和就绪，不等待隧道启动预算。停止中的状态不写为全部资源已清理，必须由后续整体监督确认。
