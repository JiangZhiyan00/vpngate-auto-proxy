# Linux／Docker 启动摘要验证

日期：2026-10-16，上海时区。

候选镜像：`sha256:161b3cc7f8e2dac127c5bae4d3af1160b405bc82e0ef98f176a2512762d7eacd`。

程序摘要：`780bff4e75a9739951ae31b6daa7e1104f4f189ce03c7ea1927dfd45ab71c8a5`。

真实容器监听后五秒内收到一次 info 启动摘要；info 和 debug 各一条，warn 和 error 均为零。文件与环境模式、不同宿主映射与未发布端口均按容器内部监听事实显示；逐字段核对地区、时区、连接上限、目录、认证布尔及日志策略，不显示宿主映射端口或凭据。首次 ready=false 与随后出口验证独立，故障及恢复不重发摘要。

四等级非法配置均以原退出码 2 失败且无成功摘要，敏感原始值未回显；缺少能力的预检失败也无成功摘要。实际绑定及端口占用反例由 logging_contract 的真实套接字测试覆盖。原状态仍为单一 JSON，返回码 0／3 和停止回收通过。

Rust 的 Linux 特权原生集成用例在当前平台按既有条件忽略，不能据编译通过认定原生执行通过。Docker 实测范围及 AppArmor 限制见[日志运行验证](deploy-logging-runtime.md)。苹果绑定与诊断保留槽尚待专用实现及验收。
