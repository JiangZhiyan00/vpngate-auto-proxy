新增三项契约测试覆盖零接口拒绝、不存在接口拒绝、无效接口 TCP 连接失败且本地可达监听未收到连接，以及固定回环接口上的真实 TCP/UDP 往返。实现前，实际收发用例因能力缺失失败；实现后全部通过。

## 首次原生实验失败与修正（2026-10-11）

用户在本机终端执行后，受控远端连接、证书校验及加密握手成功，但设备类型初始化报错并立即退出。脱敏结果见[启动失败记录](macos-tunnel-startup-failure.json)：子进程及夹具回收、宿主基线保持和清理时限检查通过，真实隧道未通过。日志没有记录新隧道接口创建，原报告接口清理字段为假不能单独解释为接口残留。

依据 [OpenVPN 2.6 官方手册](https://openvpn.net/community-docs/community-articles/openvpn-2-6-manual.html)及本地对应源码，将原生客户端改为显式 `--dev tun --dev-node utun`，固定使用原生驱动。同步将系统命令权限从级别 0 改为 1，允许内置网卡配置命令，继续禁止用户自定义脚本。

新增退出码和有界关键错误摘要，排除证书与私钥块；区分未创建接口与已创建接口的清理状态。修正后受控隔离客户端回归通过，错误摘要的长度限制及私钥排除回归通过。苹果侧真实隧道仍需重新执行，不以工具检查代替原生通过，T057/T058 保持待完成。

## 索引复用原生行为确认（2026-10-12）

2026-10-12 原生实验确认：不同远端身份的接口复用旧数字索引后，使用旧索引建立的新连接可抵达新远端，见[证据](macos-index-reuse.json)。接口名称和数字索引都不能单独作为持久出口身份。此处只确定安全约束，完整苹果后端方案仍待 T057 收口。

后端必须使旧工作进程引用在撤销后无法用于新代际；在受控停止路径中，旧业务进程及连接完全回收后才能释放接口供重建。还须覆盖接口异常消失、外部重建及检查与连接之间的竞争，不能仅通过连接前查询索引存在来宣称安全。以上机制需要独立实现和验证；当前 `index_reuse_isolation_validated` 为假。
