# 故事二：缓存、来源刷新与候选验证

日期：2026-10-10，中国标准时间。实现任务 T025—T032 已完成；T033 部分完成，三十分钟持续测试按用户要求暂缓，原生部署证据尚缺。

## 环境与复现

苹果 ARM64 主机上的独立 Debian 12 Linux ARM64 容器，使用受控 TCP/UDP OpenVPN、来源、HTTP 与域名解析服务。候选与活动使用真实独立网络命名空间、路由及私有代理套接字。夹具允许测试证书在多个独立隧道并存，未放宽产品证书校验。

在已准备工具、IPv4 转发和权限的专用 Linux 环境运行：

```sh
VAP_NETWORK_TEST=1 scripts/validate-linux.sh --case us2 --duration-seconds 1800
```

脚本运行存储与调度契约、来源刷新、缓存重启、整体重试、候选隔离及真实持续请求。单线程运行共享夹具场景，清理本次创建的夹具。名称冲突时拒绝启动，不清理既有夹具。

可用 `--duration-seconds 15` 检查测试流程，但短时结果不能替代三十分钟证据。现提供 `us1`、`us2`、`us3`、`us4` 及已有场景聚合 `all`；聚合通过只代表本次环境与指定时长，不代表全部平台或容量验收。

抓包额外需要测试环境的原始套接字能力；容器使用 `NET_RAW` 仅供测试进程抓包，不加入产品权限要求。抓取本容器夹具管理网卡，确认确实抓到节点连接及隧道封装包，再断言其中无业务目标和域名解析目标的明文包；不以空抓包认定无泄漏。

## 已取得的证据

- 10 项存储/调度契约通过：保留缓存原时间、私有目录及文件权限、原子替换、有效空快照、无效保存保留旧文件、损坏/未知版本/未来时间/来源不匹配拒绝、32 MiB 和 8 MiB 文件边界、有界诊断去重/裁剪/稳定排序、符号链接拒绝、45 节点三轮覆盖及每轮 20/并发 2、配置变更使结果和旧队列项失效。
- 6 项真实隧道集成短时试跑通过：后台检测后回收候选、来源删除活动节点仍能访问、失败刷新不改缓存时间、重启读取来源但重新建立和验证隧道、损坏诊断不影响来源恢复、整体重试不突破不同节点配额、端口/隧道成功与出口失败分别记录；端口总超时保留真实已测层次，空来源退避恢复及来源错误独立退避。
- 十五秒共存试跑完成 16 次业务请求，已有长连接往返正常，至少两轮候选验证，活动只提升一次。管理网卡抓到 3,379 条节点连接及封装包，业务和域名解析目标的明文包零条；停止后路由、系统解析、防火墙及转发值与基线一致。
- 本机 13 项单元和 38 项普通契约通过；Linux 特权场景在本机普通测试中明确忽略，另在受控容器实际运行。格式、严格静态检查及验收脚本语法检查通过。
- 故事一回归：9 项特权集成和 3 项代理契约全部通过。真实局域网设备证据沿用 `us1.md`，本次不重复开放临时端口。

## 运行行为

`nodes.json` 只保存成功获取的来源快照，来源失败保留旧快照及原时间，有效空来源写入空快照。启动恢复资料后重新验证出口，不从 `checks.json` 恢复可用、就绪或排序状态。候选过期动态显示，活动不会仅因候选过期或来源删除而关闭。

来源刷新和候选验证独立调度，长轮次不叠加；整体重试沿用本轮节点额度。后台检测完成即释放隧道，启动的待启用隧道验证后原地提升；并发上限由辅助进程统一限制为候选并发加一个活动槽。

运行汇总事件包含来源获取时间、年龄、失效及错误，以及候选有效性、轮次进度和下次调度时间。分层状态保存在当前实例的目录索引中，诊断裁剪不改变当前可用性。故事四已接入 `status` 命令与本地控制协议，见 `us4.md`。
