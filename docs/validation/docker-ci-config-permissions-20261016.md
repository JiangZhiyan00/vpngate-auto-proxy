# 发布验收配置权限修复

日期：2026-10-16（亚洲／上海）。

发布工作流在缺少能力的对照中报告退出码 2，日志为“配置无效：无法读取配置文件”。运行器创建的临时目录属主为普通用户，权限为 0700；对照容器移除全部能力后，根用户也无法遍历该目录，配置读取先于能力预检失败。

修复只调整验收夹具：该对照仅只读挂载所需配置文件，文件明确为 0644，拒绝带凭据文件配置。原私有目录及凭据文件权限不变，生产容器能力和安全策略不变，验收继续要求退出码 1 及能力诊断。

验证使用 Docker 引擎内的真实 Linux 卷，避免桌面文件共享映射影响权限：私有目录设为 1001:1001、0700，配置文件设为 0644。在全部能力移除、只读根文件系统及禁止新增权限的实例中，目录挂载复现退出码 2；单文件挂载得到退出码 1 和“缺少必要能力：CHOWN”。实验卷按本次归属标签核对后删除。

修正后的环境配置模式完整受控短试通过；能力诊断的四项单元测试通过。本机引擎未强制实施 AppArmor，这些结果不替代 GitHub Ubuntu 运行器上的强制策略验收。镜像程序未修改，仍使用此前已构建的候选镜像验证。
