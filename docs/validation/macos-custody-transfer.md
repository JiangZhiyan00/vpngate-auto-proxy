# 独立工作进程的句柄交接

日期：2026-10-12。对应 T068，延续 T067 的代际回收顺序；不表示完整苹果后端已完成。

## 交接边界

`src/platform/custody.rs` 通过父进程专属本地域流式套接字接收句柄，不接受任意描述符数字或文件路径。启动材料固定为二十四字节：四字节版本、十六字节授权标识、四字节大端接口索引；必须与可信父进程提供的预期材料一致，且恰好接收一个描述符。分段读取遵守同一单调截止，不消费后续命令；接收后设置执行时关闭标志。

`examples/macos_generation_worker.rs` 增加可选 `--custody-stdin` 启动方式，由可信父进程把专属套接字映射为标准输入。交接通过后才发布就绪事件，并将描述符交给业务代际持有；随后沿用有界命令、固定目标与登记操作撤销。既有普通管道启动方式保持可用。

授权标识与索引是启动材料的关联校验，不能独立认证对端，不能证明描述符确属目标隧道。当前仅验证可信父进程所建专属套接字对；正式资源来源、隧道身份校验、权限分工和生产子命令仍待落实。接收阶段不派生其他程序，以避开苹果系统无法原子设置执行时关闭标志的窗口。

## 失败与资源回收

缺失或多余描述符、材料不符、提前结束、超时或辅助数据截断均使工作进程启动失败，不发布就绪，不创建业务连接。已取得所有权的句柄随错误释放；启动失败必须退出独立工作进程，不能恢复接纳或在长驻辅助进程中继续运行。

本机实验发现，本地域套接字对端关闭后设置读取超时返回参数错误；错误仍按失败处理，关闭通道及进程完成回收。苹果辅助数据截断还可能包含已由内核安装、但编号未交付用户空间的句柄；本实验明确要求进程退出，并逐一检查十六个句柄对应的真实对端均已关闭，不能只凭函数返回错误宣称完整清理。

最初使用锁定的 `rustix 1.1.5` 接收接口，十六句柄超量测试触发缓冲区清理下溢及析构再次异常，进程终止。本地结果与[上游问题](https://github.com/bytecodealliance/rustix/issues/1683)描述一致；该接收路径未保留在实现中，未放宽超量拒绝要求。

接收改用固定 `unix-ancillary 0.6.1` 的安全接口，按 MIT 条款使用；核对了包内接收所有权、截断解析及执行时关闭处理。库的截断返回不等于苹果系统全部句柄已回收，仍由上述失败退出约束兜底。`rustix` 只作为苹果契约测试依赖，用于构造发送材料及检查描述符标志。项目未增加不安全代码；来源、版本和完整原始许可文本已更新至第三方清单。
