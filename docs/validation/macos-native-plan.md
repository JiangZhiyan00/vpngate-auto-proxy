
另两组独立标记分别通过活动接口和接口销毁后的旧索引发送到相同节点管理地址及端口。实验要求固定接口的流式连接均不能成功，抓包不能出现这两组业务标记；旧索引不能成功发送数据报。实验监督进程主动取消并回收自己的活动业务探针，再销毁活动隧道，确认旧索引的业务及解析探针均失败，而两个候选的业务和解析仍命中各自身份。最终检查三个隧道及抓包子进程回收、清理时限和宿主基线。

## 保留旧套接字的接口销毁实验

复现入口为：

```sh
scripts/validate-macos-tunnel.sh --case retained
```

当前电脑探针已重新构建，新环境先执行全部示例构建命令。脚本沿用三个同地址隧道和活动/候选共存场景，另外启动一个降权探针，为活动接口建立一组固定接口的流式与数据报套接字。先确认同一组套接字分别完成双向回显，再让该探针等待；监督进程仅取消独立的持续活动探针，保留本实验探针及其套接字，随后销毁活动隧道并确认接口已消失。

此时通过私有父子进程管道触发两种原套接字同时发送新的挑战，分别记录写入/发送是否成功，以及各自两秒内是否收到任何响应。部分流式数据、错误内容及空数据报也不能被当作阻断成功；流式关闭返回零字节不算业务响应。只有原探针在接口消失时仍存活、两种原套接字均未收到响应、两个候选的业务/解析继续命中各自标记，以及所有资源回收和宿主基线均通过，才标记 `retained_echo_blocking_validated`。

工具回归覆盖原套接字正常时必须检测到继续转发、关闭流式且数据报无回应时分别报告，以及部分/异常响应不能误判为阻断；均只建立一条流式连接，不重建套接字来代替旧连接。该实验只判断指定时间窗口内的原套接字响应，不以发送系统调用成功或无响应推断零直连。它不创建替代隧道、不验证接口索引复用、真实公网管理路径、异常恢复或生产自动切换。远端夹具与工具结果见[工具记录](macos-retained-tools.json)。2026-10-12 用户原生执行通过，报告已核对并归档为[保留套接字记录](macos-retained-sockets.json)：接口消失时原探针仍存活，两种原套接字在各自两秒窗口内均无响应，两个候选的业务与解析继续可用；流式写入成功、数据报发送失败均如实保留。活动连接故障前完成九轮往返，原生阶段 3.446 秒、最终清理 0.036 秒，三个外部程序正常退出，宿主基线一致，两阶段清理错误为空。无需为确认成功重复本项；该结果不证明零直连。T057/T058 保持未完成，三十分钟测试继续暂缓。

## 接口索引复用行为实验

复现入口为：

```sh
scripts/validate-macos-tunnel.sh --case reuse
```

## 实验顺序与判定

| 顺序 | 实验 | 必须满足的判定 |
| --- | --- | --- |
| 1 | 启动前记录接口、路由、系统解析配置及防火墙状态 | 能区分预先存在的资源与本实例资源；默认路由、系统解析和全局防火墙不得被测试改写 |
| 2 | 原生建立一个受控隧道，关闭服务端推送的自动路由和解析变更 | 识别本实例隧道接口、进程启动身份和连接归属；经固定接口完成数字地址访问及显式 DNS 请求 |
| 3 | 同时建立一个活动隧道和两个候选隧道 | 三个出口可分别识别；候选测试不改变活动连接、解析路径及出口 |
| 4 | 两个受控隧道使用相同内部目的地址 | 绑定不同接口的连接分别到达预期远端；冲突不能导致混用出口或借道宿主直连 |
| 5 | 对活动隧道执行中断、删除接口与重建 | 停止接受旧出口业务并取消已有连接；接口索引复用后旧引用不得转入新接口；恢复必须重新通过出口验证 |
| 6 | 请求目标恰为节点管理地址，并在断隧道时发起业务及 DNS 请求 | 业务不能借用 OpenVPN 管理连接的宿主路径；受控远端观测与抓包均无业务或 DNS 直连 |
| 7 | 正常停止、强制终止及遗留恢复 | 在既定总时限内只清理本实例确认资源；不结束无关进程、不删除预先存在接口；无法确认归属时明确失败 |
| 8 | 对照启动前基线并检查剩余进程与资源 | 默认路由、系统解析和全局防火墙保持不变；本实例接口、进程和临时资源均已回收 |

固定接口套接字只是当前待验证方案的一部分。若以上实验不能证明隔离与故障阻断，先修订方案，不将该原型直接接入生产转发路径。

## 隧道控制句柄生命周期候选方案

```sh
scripts/validate-macos-lease.sh
```

本项不连接远端，不配置业务地址和路由，不启动外部隧道程序。只创建本次控制套接字对应的临时接口，将一个继承描述符交给降权子进程；监督进程保留自己的描述符。强制终止并回收借用进程后，接口名称和数字索引必须保持。使用首次连接前明确指定且连接成功的控制单元编号尝试第二次连接，必须得到明确的单元占用错误；不能从接口名称推导控制单元，不能将权限错误当作占用通过。另建一个动态接口，要求其名称、索引和控制单元与保留接口均不同。
