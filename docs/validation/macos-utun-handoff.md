## 身份校验

`src/platform/custody.rs` 增加持有控制句柄的封装。接收方先完成原有私有启动通道的版本、授权材料、非零索引及唯一描述符检查，再从收到的句柄读取套接字类型和隧道接口名称；只接受数据报控制句柄、严格的隧道接口名称和与预期相同的实际接口索引。失败时关闭已接收描述符并退出独立工作进程，不发布就绪或创建业务连接。

封装只公开接口名称及转入业务代际的入口，不提供原始描述符、读写、断开或继承操作；代际正常退休继续先取消并等待登记操作释放，再关闭控制句柄。可信父进程负责创建本实例控制连接与专属通道，校验不代替父进程授权，也不防御其他管理员主动破坏接口。此前已确认的保证范围继续生效。

本项目使用固定 `nix` 0.31.3 的安全接口，没有增加本项目不安全代码。接口名称查询依据见[依赖上游实现](https://docs.rs/crate/nix/0.31.3/source/src/sys/socket/sockopt.rs)，本机包源码及许可已经核对。苹果公开实现的控制选项返回接口名称，见[公开隧道实现](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/net/if_utun.c)；公开主分支不能代替目标系统的原生行为验收。

受控工作进程新增 `--utun-custody-stdin` 严格入口，在校验后才输出接口名称及就绪。原 `--custody-stdin` 只用于普通套接字生命周期回归，不得作为真实隧道启动入口。两者均为实验示例参数，尚未成为正式服务内部命令。

## 原生实验

`scripts/macos_handoff.py` 通过受控工作进程执行以下检查：

1. 交接真实第三条隧道句柄，但提供第一条接口索引；必须非零退出且没有任何就绪输出，父方接口身份保持。
2. 正确交接第三条句柄，在降权工作进程中校验真实名称及索引，完成固定接口流式与数据报业务正向往返。
3. 编排方明确关闭原句柄，再强制终止并回收第三条隧道进程；业务代际仍存活，旧接口身份保持，其他两条隧道业务及解析归属正确。
4. 撤销第三条工作代际，确认正常退休和退出，再观察最后持有者释放后的接口消失，并核对所属路由回收。
5. 对第二条隧道重复正确交接及业务正向往返；编排方关闭原句柄，隧道强制退出后身份保持，再强制终止并回收工作进程，检查接口自动消失。

每个工作进程在发送句柄前登记，失败回收沿用先确认所有登记业务进程退出、再释放隧道资源的顺序。活动第一条长连接继续运行；外层检查宿主网络基线、接口及进程回收、清理预算和夹具回收。任一错误阻止通过，不以异常退出或接口仍存在作为成功。

工具回归已通过：两项新增契约、十六项独立工作进程测试（含新增真实入口的三类无关描述符拒绝）、七项新增阶段回归；完整苹果工具回归一百一十八项通过。完整普通回归为十三项单元、六十三项普通契约；三项特权契约与二十九项特权集成没有执行。格式、严格静态检查、示例构建、脚本语法检查及许可材料更新通过。两种承载各三个受控远端夹具结果单独保存在[工具证据](macos-handoff-tools.json)。

工具准备时，本会话在管理员及防火墙读取预检受阻，未创建宿主接口。随后用户已在本机普通用户终端完成以下两次原生验收，当前无需重复执行：

```sh
scripts/validate-macos-tunnel.sh --case handoff --transport tcp
scripts/validate-macos-tunnel.sh --case handoff --transport udp
```

包装入口在原生阶段请求管理员权限，使用现有固定实验依赖并检查来源、补丁及二进制摘要。两次报告均为成功、真实交接验证字段为真且各阶段与最终清理错误为空，本项限定验收已完成。失败时仍须保留报告和诊断，不放宽门槛。

本项不观测故障后原套接字的两秒响应，不能替代此前的双重故障实验，也不证明零直连、正式监督服务崩溃保护或异常重启安全。完整业务与解析封装、真实管理路径、常规网络变化、资源归属与安全重启仍待 T057/T058 推进。三十分钟测试继续暂缓。
