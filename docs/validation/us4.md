# 故事四：命令、生命周期和容器交付

日期：2026-10-10，中国标准时间。

## 环境与已取得证据

开发主机为苹果 ARM64；受控生命周期测试在独立 Debian 12 ARM64 容器执行，实际运行镜像为 Alpine 3.22 ARM64。未使用全特权、宿主网络、宿主空间、放开系统调用过滤或关闭禁止新增权限。

普通命令契约六项通过：无权限帮助/版本、隐藏内部命令、状态纯机器输出及就绪退出码、未知字段脱敏拒绝、重复停止及总停止时限、零/超长/恰好六十四千字节控制帧和五秒读取超时。帧长度边界使用真实本地套接字，超时单独使用虚拟时钟，避免时钟先于套接字就绪而产生误报。

生命周期真实集成验证覆盖：

- 状态全部契约字段、无秘密输出，非法版本/命令/额外字段/超长控制帧拒绝，正常停止十五秒内完成、运行资源清除、来源数据保留。
- 无节点时普通状态成功而就绪检查返回 3；查询不增加来源请求；终止信号正常清理并返回 0。
- 端口占用和必要网络能力缺失在启动时失败，回收本次创建的运行目录。
- 初始化部分失败回收本次私有目录，保留不明归属资料。
- 强制结束父进程后，重启核对并回收已记录的遗留子进程及网络空间，新实例重新验证出口。
- 进程启动身份变化或网络空间存在未记录进程时，回收操作在发送信号前拒绝；原进程保持存活。

最终九项生命周期用例全部通过，耗时 3.32 秒，未忽略：在仅限本次子进程的私有挂载空间遮蔽隧道工具，启动明确报缺依赖并回收目录，父测试环境的工具保持可用；两个候选隧道已连接且出口请求尚未完成时停止，全部已记录隧道/工作进程与网络空间均被回收。

实际运行镜像通过受控短时验收：认证正确返回 204、错误密码与无认证拒绝；只读根文件系统正常运行；本地状态可查询；停止并删除旧容器后用同一数据卷创建新容器，来源失败时依靠保留原时间的缓存恢复并重新验证；出口故障后阻断请求、恢复后重新放行；回环监听不能通过发布端口从外部访问；缺能力明确失败；正常停止不足十五秒且退出 0。测试结束删除本次带归属标签的容器、网络、卷及随机凭据。

首次镜像运行发现动态展开运行库缺失，补充 `libgcc` 后重新构建，以上镜像验收通过。没有以构建成功代替运行成功。

## 复现入口

```sh
VAP_NETWORK_TEST=1 scripts/validate-linux.sh --case us4 --duration-seconds 15
scripts/validate-docker.sh --case smoke
```

后者构建镜像，创建独立桥接与真实受控隧道，不访问公共节点。使用已有最新镜像时可加 `--skip-build`。测试抓包需要的能力只加到测试容器，产品镜像配置不加原始包能力。

专用应用安全策略经 Debian 解析器检查通过。当前引擎报告系统调用过滤和控制组空间，没有启用应用安全模块，未完成策略强制实施。`--require-apparmor` 或 `--case all` 在缺少该模块时明确失败。

## 任务状态与边界

命令、控制通道、停止与恢复、镜像、安全策略文件和部署配置已经实现。启动实际探测独立网络空间、私有挂载及隧道设备，缺少能力或工具及时报错。安全策略强制实施、能力逐项缩减、Linux x86_64 原生及 Ubuntu 24.04 矩阵尚缺，因此 T049 保留未完成。苹果系统原生后端尚未实现，不能用本机容器替代。
