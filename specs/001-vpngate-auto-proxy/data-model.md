# 数据模型

## 容器环境配置适配（需-022，2026-10-15）

`.env` 是镜像仓库部署的用户配置来源；编排只传入明确映射的参数，生成 AppConfig 后仍按原模型校验。镜像、宿主发布地址及端口属于部署参数，不进入程序配置；代理凭据仍为独立秘密文件。公开配置在只读根容器的 `/tmp` 临时挂载中以独立 `0600` 文件生成，固定数据及运行目录不允许环境覆盖；配置不持久化到缓存卷。原生及旧容器文件模式不读取环境适配参数。

2026-10-13，T098 在苹果路径增加单实例公开运行目录：特权父进程持有操作系统独占锁和实际节点登记，控制监听描述符交给已核验的低权限控制进程。状态来自来源协调器的同一观察通道；停止响应包含实例标识和预算，随后显式关闭特权候选池。正常停止只删除设备号和节点号仍匹配且无未知内容的本实例节点。持久崩溃恢复清单尚未实现，见[记录](../../docs/validation/macos-public-instance.md)。

2026-10-13，T096 内部候选检测结果新增特权侧实际完成时间，协调方以该时间确定诊断完成及过期，不因轮询或控制请求排队延长有效期。此墙上时间不能替代特权侧单调时钟提升凭据。协调停止状态清除就绪及活动引用，但保持“停止中”，须由完整监督确认所属回收后才可宣称停止完成。见[记录](../../docs/validation/macos-source-coordinator.md)。

## 苹果内部健康检测增量（2026-10-13）

T093 的健康结果只作当前代际历史诊断，包含工作标识、代际标识、单调递增轮次序号、起止时间，以及出口检测报告或监督错误。单个通道仅保留最近一条，不形成无限事件队列。撤销后旧成功结果不能恢复可用性；使用方必须同时核对活动归属和撤销令牌。检测会话与每次直属检测分别登记回收，整个会话释放前不能确认代际清理完成。该内部结果尚未接入苹果公开状态或持久恢复清单，T058 保持未完成，见[记录](../../docs/validation/macos-active-health.md)。

输入：[功能规格](spec.md)。单实例、单写入者，无数据库。
字段名是程序契约；正文和默认显示使用简体中文。持久时间采用 UTC；运行日志使用配置的 IANA 地区时区，默认上海。

## 节点与端点

| 字段 | 约束 |
| --- | --- |
| `id` | 对来源类型、规范化 IPv4、端口、承载协议取稳定摘要 |
| `endpoint` | `{ip, port, transport}`；公开 IPv4、1—65535、`tcp` 或 `udp` |
| `source_hostname`、`country` | 来源元数据；country 用于候选地区筛选，不用于构造远端端点 |
| `profile`、`profile_digest` | 净化的连接资料及摘要；私有文件，不进入状态或日志 |
| `source_fetched_at` | 来源最后成功获取时间，缓存读取不刷新 |
| `present` | 是否仍存在于最后一次成功解析的来源列表 |
| `last_attempt_at` | 用于轮转公平性；未检测优先，之后最久检测优先，同序按 id |

同端点与同协议合并为一个节点；同批冲突配置拒绝该冲突节点并记录，不能随机覆盖。
同 id 的配置摘要改变时，清空既有验证与排队中的旧配置任务。
来源删除活动节点只改变 `present`，活动出口仍健康可继续；断开后不能再次选择已删除节点。
端点在每次创建工作进程前重新校验，远端配置不能覆盖端点。

## 来源快照

`schema_version=1`、`source_url`、`fetched_at`、节点列表与解析统计。
输入限制 16 MiB、20,000 行、单解码配置 256 KiB，超限整次刷新失败；坏行统计后跳过。
缓存文件 `nodes.json` 最高 32 MiB，过大、损坏或未知模式版本拒绝读取，转为等待有效来源。
来源全部无效或返回空列表，按一次有效的空快照处理，不把旧节点伪装成仍在来源中。
网络、完整响应或模式解析失败保留旧快照，标注最后错误。
来源缓存默认 24 小时；时间在未来或系统时钟回拨导致无法判断时按失效处理。

## 验证结果与尝试

| 字段 | 内容 |
| --- | --- |
| `node_id`、`profile_digest` | 结果只关联对应配置版本 |
| `layer` | `port`、`tunnel`、`exit` |
| `outcome` | `not_tested`、`running`、`succeeded`、`failed`、`expired`、`not_applicable` |
| `started_at`、`finished_at`、`elapsed_ms` | 时刻与单调时钟耗时 |
| `attempts` | 本次地址尝试次数及最终状态码或错误分类，不保存正文 |
| `expires_at` | 出口候选结果有效期，默认 15 分钟 |
| `failure_reason` | 超时、握手失败、响应失败、配置拒绝等稳定分类及中文说明 |

端口成功不推导隧道成功，隧道成功不推导出口成功。
UDP 承载的 TCP 快速探测记为 `not_applicable`，继续真实握手验证。
结果过期时动态显示 `expired`，不写成节点失败；历史结果跨重启只作诊断，不参与可用排序。
活动健康检测独立于候选结果有效期，不因候选过期而断开健康活动隧道。

## 运行配置

模式版本、监听、凭据文件、数据和运行目录、来源 URL、允许国家/地区、显示时区、各周期和超时、候选轮次配额、
候选并发、出口地址列表、最大尝试次数、重试与退避、连接上限及停止时限。
完整字段、默认值与交叉校验见[配置契约](contracts/config.md)。
配置运行中只读，重启生效；状态仅输出脱敏配置摘要，不输出凭据或节点配置。

### 地区及时间扩展（需-019、需-020）

| 字段 | 约束 |
| --- | --- |
| `countries` | 默认 `[]`，最多 256 项；每项恰为两位 ASCII 英文字母，匹配来源 `country` 时大小写不敏感；不自动去掉空白或扩大允许集合 |
| `timezone` | 默认 `Asia/Shanghai`；必须为已支持的 IANA 名称；启动解析，旧配置省略时采用默认值 |
| 状态 `timezone` | 名称字符串，供人类可读时间转换；新版客户端接收旧消息缺字段时默认上海 |

完整来源快照与筛选后候选视图是两种视图：快照节点及解析统计描述原有效来源，候选汇总只计算当前筛选后的目录。筛选不修改 `fetched_at`，不改变历史结果不得恢复可用性的规则；改变配置必须重启。刷新后筛选视图为空仍沿用此前合规健康活动出口的原维持规则，无健康活动出口时才等待，断开后不从范围外节点恢复。

检测时间、缓存和状态机器时间保持 UTC；日志及人类显示转换为带实际偏移的同一时刻，耗时仍由单调时钟计算。宿主与容器环境时区不参与配置优先级。

## 工作进程与活动出口

`worker_id`、`instance_id`、`node_id`、配置摘要、角色、命名空间与接口归属、
子进程 pid/启动身份、私有套接字路径、生命周期、最近验证、取消令牌。

生命周期：已分配 → 建隧道 → 验证出口 → 活动或完成检测 → 停止 → 已清理。
任一步骤失败转停止与清理。后台检测完成后释放候选；之后启用该节点时重新连接并验证。
首次启动或故障恢复创建的待启用隧道，在其实际出口验证成功后直接提升为活动出口，
不先释放再重建；待启用时占候选槽，提升后转为活动槽，不增加额外工作槽。
默认最多一个活动和两个候选；替代出口占候选槽，关闭旧活动后提升，不创建额外备用槽。
实际上限随 `candidate_concurrency` 配置变化，不能为绕过检测配额新开任务。

服务状态：

```text
启动中 → 获取节点／验证中 → 就绪
获取节点／验证中 → 等待节点 → 验证中
就绪 → 切换中 → 验证中 → 就绪
切换中／验证中 → 等待节点
任一运行状态 → 停止中 → 已停止
```

仅“就绪且活动出口引用有效”允许转发。
单次检测最多请求配置的次数，默认 3 次；有一次成功保持就绪，
全部失败或总时限耗尽立即撤销引用并取消旧连接。
不保存或维护连续多轮失败阈值。结构性隧道故障立即阻断，不等 HTTP 检测。

## 连接配额与事件

全局客户端配额默认 50，从接入、认证、目标连接到转发结束均持有；失败、取消、断开即释放。
内部出口检测桥接不占对外客户端配额，使用独立有界槽，避免满载时无法健康检测。
候选验证仍受候选并发配额；活动健康检测最多一个，不堆叠。

事件含带时区时间、事件类型、节点/工作进程标识、状态变化、原因和耗时。
不含密码、证书私钥、完整配置、代理目的地址或访问正文；检测地址仅记列表索引，避免查询参数泄密。
输出到标准错误，容器由日志系统管理；不新增数据库或无界内存历史。

## 持久化、锁与清理

`nodes.json` 保留来源资料；`checks.json` 仅保存最新诊断摘要，不保存逐次请求历史。
诊断文件固定上限为 8 MiB、最多 2,048 条，每个节点及检测层次组合最多保留一条；
条目只含本模型验证结果字段，`attempts` 为次数及最终状态/错误摘要，失败说明最多 512 个 UTF-8 字节，按字符边界截断。
成功刷新来源后删除既不在来源中也不是当前活动节点的诊断条目；
剩余条目按完成时间新到旧保留，同时间按节点 id、层次排序，写入前裁至条目及字节上限。
读取时先检查大小；超限、损坏或未知模式版本则忽略诊断文件并记录原因，
不影响有效来源缓存的读取，也不恢复可用或就绪状态。
这些限制同样适用于待持久化的诊断历史；当前节点可用性与调度状态独立维护，
不能因诊断淘汰把节点标记失败或撤销健康活动出口。
数据目录 `0700`，敏感文件 `0600`，写入同目录临时文件后同步、原子替换；单控制进程写入。
运行目录放实例锁、控制套接字和 `resources.json`，不与缓存一起恢复活动状态。
实例锁必须是进程持有的操作系统锁，不能只凭 pid 文件认定进程身份。

资源清单含实例标识、接口/命名空间名、规则表和 pid 启动身份；
再次启动只回收确认属于本实例的资源，身份不一致时停止并说明，不删除其他进程资源。
所有时间预算在运行中用单调截止；重启后的来源年龄用持久时间计算。

## 版本交付与发布状态（需-021）

| 字段或材料 | 关系与约束 |
| --- | --- |
| 稳定版本标签 | 严格 `v0.0.0` 形式；三段均为零或无前导零的非负整数，不接受预发布或构建后缀 |
| 目标镜像 | 小写 `命名空间/仓库:版本标签`，固定 Linux amd64；不包含凭据，不隐式更新通用最新标签 |
| 镜像身份与程序摘要 | 记录实际验收镜像身份及程序 SHA256；推送该镜像，远端验收以镜像配置摘要及架构核对身份，不混淆镜像配置摘要与仓库清单摘要 |
| 完整源码材料及摘要 | 对应版本项目源码、锁定原包、系统包来源与配方、原始声明；归档 SHA256 及文件清单可核对 |
| 验证记录 | 明确实际环境、范围和状态；本地准备通过与远端已公开是不同状态，不含密钥 |

阶段：配置校验 → 代码回归 → 构建及分发核验 → 受控镜像短试 → 冻结材料 → 公开源码附件 → 推送镜像 → 远端拉取核验。任一前置失败禁止进入后续推送；附件公开后失败可以留下附件，不能推导镜像发布成功。真实发布前不将本地 `status=passed` 解释为已公开。
