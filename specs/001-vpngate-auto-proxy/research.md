## 容器单一环境配置决策（2026-10-15）

用户选择只维护 `.env`。采用程序自身转换并校验公开配置，再由容器入口生成私有临时 JSON；复用现有序列化与校验，不新增运行库或脚本解释器。保留独立凭据文件、显式文件模式及固定容器路径。相较手工维护两份配置，避免重复；相较 shell 拼接 JSON，避免引号、类型与网址转义错误。编排使用官方支持的清除/覆盖标记移除构建与用户 JSON 挂载，需要 2.24.4 或更新版；修改环境须重新创建容器，普通 restart 不加载新环境。网络隔离、许可依赖及安全策略无新增范围，正式发布仍须重建并冻结匹配来源。

## 业务与解析网络入口增量（2026-10-12）

苹果[技术说明 TN3165](https://developer.apple.com/documentation/technotes/tn3165-packet-filter-is-not-api)明确指出，系统报文过滤器不是面向广泛分发产品的应用接口，规则可能与系统或其他程序冲突。因此正式苹果后端不得以安装全局过滤规则作为唯一故障阻断机制。苹果开发者关于接口选择的[说明](https://developer.apple.com/forums/thread/798519)列出 `IP_BOUND_IF` 和 Network 框架的必需接口设置；本项目目前采用前者，但固定接口不代替业务代际撤销、句柄生命周期及实际公网路由验证。现有原生实验只为受控目标添加按接口限定的主机路由，不能外推到任意公网目的地址。此处依据官方资料与现有代码形成设计约束；公网路由和正式服务仍须实测与实现。

T071 将已核验的真实控制句柄、固定接口与不可重新启用的业务代际组合成单一网络入口，业务方不取得裸出口套接字或数字接口索引。流式转发和解析收发均在登记操作内持有套接字；撤销会关闭进行中的资源，退休确认在它们释放后返回。入口已在出口创建前拒绝非公网业务及解析目标，并可接收工作进程私有套接字。六项普通权限真实套接字测试覆盖截断解析的同接口重试、撤销、目标拒绝及资源释放，见[验证记录](../../docs/validation/macos-generation-network.md)。正式服务、完整地址解析、进程权限及异常重启尚未接入，T057、T058 保持未完成。

## 二、运行栈与存储

**决策**：Rust 2024，沿用上游 Rust 1.90 构建基线，采用 Tokio、Clap、Serde、Reqwest、CSV、
Base64、Blake3、Chrono、URL、UUID、Zeroize 和 Tracing；测试复用属性测试及临时目录工具。
随机选择使用 `rand`，在实施时锁定与工具链匹配的版本。
移除 Axum、网页 TLS 服务、SQLx、网页静态资源与相关专用依赖。

**理由**：以裁剪现有实现减少开发量；无需 Python 与 Rust 两套服务，也不需要数据库、网页或任务平台。
运行时只保留一个控制进程、一个特权辅助进程、必要的隧道和工作进程。
默认一个活动隧道、最多两个临时候选；并发配置增大时同步调整工作槽上限。
后台检测结束释放候选，不常驻备用隧道；启动或恢复创建的待启用隧道验证成功后直接提升为活动出口。

**备选**：Python 更容易编写控制流程，但会丢失已获明确许可的现成隔离和认证模块；
整套 SQLite 对单实例缓存和状态过重，选原子 JSON。

版本证据：[依赖清单](https://github.com/Uber-Eins/vpngate2socks/blob/a4ba00b3bb081dd3b192c0ea8a1dce56a19886ad/Cargo.toml)、

## 三、直接连接与隔离

**决策**：来源获取在控制进程直连；每个隧道拥有私有网络空间、虚拟网卡、固定 IPv4 节点端点、
隧道内 DNS 和文件系统路径型私有代理套接字。保留特权辅助进程边界。
OpenVPN 同时支持 TCP 和 UDP 承载；代理业务仍只支持 SOCKS5 CONNECT。

**理由**：原核心强制上游 SOCKS5 与本项目无上游要求不符。
删除上游配置必须同时替换防火墙、路由及类型化请求，不能只删代理参数。
TCP/UDP 区分贯穿配置白名单、缓存、节点标识、控制协议与护栏；UDP 端点不做 TCP 快速探测。

**备选**：共享活动路由做候选测试会影响现有代理；仅不同虚拟网卡不足以证明隔离。
不采用宿主全局路由切换、不采用宿主网络、不采用全特权容器。
详细路径、能力与清理规则见[网络契约](contracts/network.md)。

依据：[OpenVPN 2.6 手册](https://openvpn.net/community-docs/community-articles/openvpn-2-6-manual.html)、
[网络命名空间](https://man7.org/linux/man-pages/man7/network_namespaces.7.html)、
[路径型套接字](https://man7.org/linux/man-pages/man7/unix.7.html)。

## 四、出口验证与切换

**决策**：活动与候选共用验证器。每次独立随机抽取地址，允许重复，默认最多 3 次；
使用 GET，最终 2xx 即成功，不读取完整网页正文、不要求非空响应，允许最多 5 次跳转。
所有 DNS、桥接、连接、TLS、响应头及跳转均计入本次总时限。
每次尝试按剩余时限除以剩余尝试数分配预算，防止首个慢地址耗尽全部机会；
一次失败立即下一次，成功立即停止，外层绝对截止强制终止。

默认地址列表为 `https://www.gstatic.com/generate_204` 和
`https://cp.cloudflare.com/generate_204`，可换成普通网页。
规划时当前环境直连 GET 两者均返回 204、空正文；这是地址选择依据，不能证明任意 VPN 节点可达。
配置只接受 HTTP/HTTPS；HTTPS 验证证书，忽略环境代理，所有目标请求经指定工作进程。

活动检测失败立即清空活动引用、关闭旧连接并切换；不保留原核心的旧隧道排空时间。
启用替代出口前重新完成实际隧道的出口验证，验证成功后直接提升该待启用隧道。
首次启动同样只建立并验证一次待启用隧道，不走后台检测完成后释放再重建的路径。
全部不可用时退避并继续运行。

**备选**：严格 204、响应体非空、连续多轮失败、要求特定业务网站，均被已确认需求排除。

## 五、数据生命周期与恢复

**决策**：数据目录保留节点快照与诊断结果，运行目录保留实例锁、控制套接字和资源归属记录。
来源缓存有效期 24 小时；重启保留来源时间但不恢复就绪或候选可用状态。
配置内容改变使该节点既有验证失效；失败刷新不覆盖旧快照。
JSON 经同目录临时文件、同步及原子重命名写入；文件限制见[数据模型](data-model.md)。
诊断历史只保留最新摘要，固定上限 8 MiB、2,048 条；失败说明最多 512 个 UTF-8 字节。
来源更新删除失去归属的历史，超限按时间淘汰；诊断损坏或裁剪不影响有效来源缓存与当前可用性。

**理由**：确保容器替换可以恢复节点资料，又不把历史结果误当当前可用。
进程内截止采用单调时钟；持久时间使用 UTC，显示按实例地区时区，默认上海（需-020 于 2026-10-15 扩展原默认显示行为）。

**备选**：每次重新获取无法满足来源不可用时恢复；持久化活动隧道句柄不安全且无必要。

## 八、苹果系统原生适配的可行性记录

## 2026-10-15 地区、时区与版本发布决策补审

本节记录已有实现的设计审查，不能表述为实现前已完成研究。依据为用户三项需求、两个仓库均公开的确认，以及当前源码、锁文件和[功能验证记录](../../docs/validation/docker-features-20261015.json)。

### 国家/地区筛选

**决策**：使用已有来源 `CountryShort` 元数据，在来源和缓存进入候选目录之前统一筛选；完整快照继续写缓存。空配置接受全部，代码大小写不敏感，限制最多 256 项、两位英文字母，不匹配时等待。

**理由**：只过滤下载结果会使重启时旧缓存绕过规则；裁剪缓存会使更换允许地区后失去仍有效的数据。元数据筛选不替代实际出口验证，不引入地理位置数据库或新的网络请求。

**备选**：仅刷新时过滤、覆盖缓存为筛选子集、无匹配时放宽地区，均不能满足 US5 的恢复和不回退行为。格式合法但未知代码按无匹配处理，不承诺独立验证节点地理位置。

### 运行时区

**决策**：锁定 `chrono-tz 0.10.4` 的地区规则，配置为名称，显式传给日志及人类状态显示。机器时间和缓存继续 UTC，调度继续单调时钟；旧状态缺字段默认上海，宿主与 `TZ` 不覆盖实例配置。

**理由**：固定偏移不能处理纽约及悉尼夏令时；依赖宿主设置不能保证跨地区容器一致。嵌入规则避免增加系统时区包或运行时下载；配置错误可在启动前拒绝。

**备选**：固定 `+08:00`、通过修改进程全局环境读取宿主本地时区、依赖容器系统时区文件，分别存在无夏令时、全局副作用或额外环境依赖。规则更新须升级锁定依赖并重建，不承诺已部署旧镜像自动获得未来地区规则变更。

**依赖与许可**：锁文件新增 chrono-tz、phf、phf_shared、siphasher；精确版本及原文见 Cargo.lock 和 `docs/third-party/inventory.json`。本次材料采集包含 218 个完整锁定原包、399 份嵌套声明；数字为该验证产物历史事实，后续版本应重新采集，不能固定写成未来要求。

### 版本发布

**决策**：版本以严格 `v主.次.修订` 稳定标签命名，GitHub 工作流固定 Linux amd64；复用现有采集、核验及打包工具。两个公开仓库；先公开同名版本完整源码附件，再推送已验收镜像，不更新 `latest` 或覆盖已存在附件。

**理由**：避免分发未完成来源义务的镜像；推送时重建可能偏离已验收产物。固定已验收架构避免将构建成功误称为其他架构已支持。远端凭据以 GitHub 密钥管理，仓库名以变量传入。

**备选**：仅构建后直接推送不能覆盖现有分发门槛；仅上传受访问权限限制的临时构建附件不满足本次公开源码提供方式；同时发布未验收多架构或通用最新标签会增加当前交付范围。

**验证边界**：本地代码回归、语法与完整准备流程已有证据；真实 GitHub 执行、附件可公开获取及 Docker Hub 拉取需 T111、T112。T117 已按容器引擎首段名称解析语义限制目标，拒绝含点的命名空间和 `localhost`，不增加多注册表能力。当前不新增依赖或技术选择，无未决研究项；本节不是重新运行公网试验的记录。
