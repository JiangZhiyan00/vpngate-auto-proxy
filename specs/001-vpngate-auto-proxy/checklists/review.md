# 综合需求质量清单：自动节点获取、验证与局域网代理

**目的**：在任务拆分前，以标准深度审查核心需求是否完整、清楚、一致且可衡量。
**创建日期**：2026-10-10（中国标准时间）
**功能**：[功能规格](../spec.md)
**依据**：[实施计划](../plan.md)、[研究决策](../research.md)、[数据模型](../data-model.md)、[配置契约](../contracts/config.md)、[网络契约](../contracts/network.md)、[命令行契约](../contracts/cli.md)
**适用人员与时机**：项目作者或审查者；技术规划完成后、任务拆分前。
**审查范围**：节点获取与检测、故障切换、隔离与访问控制、原生及容器部署、精简与源码复用。按用户要求，本轮不包含参考仓库许可证审查。

**生成说明**：由 `$speckit-checklist` 根据当前需求及用户选定范围生成。
**审查所有权**：此清单由审查者维护；仅在审查者认定需求文字满足相应质量标准后勾选。
**标记含义**：勾选表示需求质量已审查并符合要求，不表示程序已经实现或通过运行验证。全部新增条目保持未勾选。

## 需求完整性

- [x] CHK001 是否完整定义节点获取、刷新、去重、持久缓存、重新验证和启用出口的主流程，并明确各阶段的失败去向？[完整性，规格 §需-001、§需-004、§需-007]
- [x] CHK002 是否分别定义端口、隧道和出口三层结果，并明确不适用端口快速探测时的状态与后续验证要求？[完整性，规格 §需-002；数据模型 §验证结果与尝试]
- [x] CHK003 是否完整规定多检测地址、独立随机允许重复、可配置最大次数、任意最终 2xx 成功即停止及空响应体成功的判据？[完整性，规格 §需-002、§运行参数与默认行为]
- [x] CHK004 是否定义候选调度、活动检测和来源刷新的独立职责，以及启动或故障恢复提前检测时的配额和不叠加约束？[完整性，规格 §需-003；配置契约 §检测与重试语义]
- [x] CHK005 是否明确本地帮助、启动、状态和停止所需信息，以及容器配置、凭据、端口和缓存保留的完整使用路径？[完整性，规格 §需-010 至需-012；命令行契约 §命令]

## 需求清晰度

- [x] CHK006 是否清楚区分地址请求尝试、节点整体重试和多轮恢复退避，避免将默认三次地址尝试解释为连续三轮失败？[清晰度，规格 §需-006、§运行参数与默认行为；配置契约 §检测与重试语义]
- [x] CHK007 是否明确候选与活动出口的总超时边界、跳转和解析所占预算，以及预算耗尽后停止尝试的规则？[清晰度，规格 §需-002、§需-016；配置契约 §字段与默认值、§检测与重试语义]
- [x] CHK008 是否将“可用”“就绪”“过期”“等待节点”区分为可判断状态，并说明普通检测成功不保证所有业务目标可访问？[清晰度，规格 §需-002、§需-014、§假设；数据模型 §验证结果与尝试]
- [x] CHK009 是否明确单活动出口、切换时关闭旧连接及由客户端重连的边界，避免形成无损迁移或常驻备用隧道的隐含承诺？[清晰度，规格 §需-007、§边界情况、§假设；数据模型 §工作进程与活动出口]
- [x] CHK010 是否清楚区分隧道承载的流式或数据报协议与首版代理仅支持流式连接、IPv4 业务目标的范围？[清晰度，规格 §需-008、§假设；网络契约 §无上游的直接连接]

## 文档一致性

- [x] CHK011 规格、配置契约与数据模型中的默认间隔、次数、有效期、并发、连接配额和退出时限是否一致，且可配置值与固定验收基线有清楚区别？[一致性，规格 §需-016、§运行参数与默认行为；配置契约 §字段与默认值；数据模型 §运行配置]
- [x] CHK012 启动前验证、单次活动检测失败立即阻断和隧道结构故障立即阻断的要求，是否在规格、状态模型和网络契约中一致？[一致性，规格 §需-004、§需-006、§需-007；数据模型 §工作进程与活动出口；网络契约 §发布、故障与取消]
- [x] CHK013 来源缓存有效期、候选结果有效期和健康活动出口的生命周期是否始终独立，避免缓存过期误停健康出口或历史结果恢复就绪？[一致性，规格 §需-001、§边界情况；数据模型 §来源快照、§验证结果与尝试]
- [x] CHK014 默认回环、非回环必须认证、容器端口发布与授权设备访问的要求是否一致，且没有把发布端口等同于已正确配置监听？[一致性，规格 §需-009、§需-011；配置契约 §实例与校验顺序；命令行契约 §SOCKS5 契约]
- [x] CHK015 “宿主既有网络设置保持不变”是否与原生部署所需的预先配置转发、防火墙路径及本实例新增资源边界一致？[一致性，规格 §需-005、§成-006；网络契约 §无上游的直接连接]

## 验收标准可衡量性

- [x] CHK016 首次可用和故障恢复时限是否给出明确起止点、节点连接条件和受控环境前提，能够区分服务开销与公共节点延迟？[可衡量性，规格 §成-001、§成-003、§可衡量结果]
- [x] CHK017 候选轮转验收是否明确节点规模、每轮配额、并发、覆盖顺序与未检测节点的分类，足以客观判断公平性及不遗漏要求？[可衡量性，规格 §成-002；规格 §需-003]
- [x] CHK018 隔离与故障阻断的成功标准是否明确观测的业务流量、业务域名解析和宿主网络变更范围，并与允许的控制流量区分？[可衡量性，规格 §成-003、§成-004、§运行参数与默认行为]
- [x] CHK019 容量标准是否明确设备数、连接总数、认证及建连占额、持续时长、超限行为及资源记录口径，而非未经测量的硬件预算？[可衡量性，规格 §需-018、§成-009；数据模型 §连接配额与事件]
- [x] CHK020 出口检测验收是否覆盖不同最大次数、成功即停、最终 200 或 204、随机地址合法性及总超时，且不要求随机过程必然遍历全部地址？[可衡量性，规格 §成-010、§运行参数与默认行为]

## 正常、异常与恢复场景覆盖

- [x] CHK021 是否定义来源不可达、有效空列表、全部条目无效与缓存损坏或过期的不同处理，明确何时保留旧快照、何时更新为空？[场景覆盖，规格 §需-001、§边界情况；数据模型 §来源快照]
- [x] CHK022 是否完整定义全部节点不可用时的持续运行、退避、等待状态和后续恢复规则，且容器存活判断不会将等待误判为必须重启？[恢复覆盖，规格 §需-007、§成-008；命令行契约 §控制套接字与状态字段]
- [x] CHK023 是否覆盖候选检测失败、替代节点连接失败及检测地址自身故障，并避免把检测失败单独表述为节点确定离线？[异常覆盖，规格 §需-002、§需-006、§边界情况；网络契约 §发布、故障与取消]
- [x] CHK024 是否定义启动部分失败、正常停止、异常退出后再次启动及容器替换的资源与状态恢复边界，只清理能够证明属于本实例的资源？[恢复覆盖，规格 §需-013、§成-005、§成-006；网络契约 §退出与遗留清理]

## 边界条件覆盖

- [x] CHK025 是否定义单地址列表、空列表、非法参数、时间溢出、未知配置字段和不可分配并发数的处理，避免无界请求或隐式采用错误配置？[边界覆盖，规格 §需-016；配置契约 §字段与默认值]
- [x] CHK026 是否定义同端点重复或冲突资料、节点配置变更及来源删除节点时，历史结果和当前活动连接的不同处理？[边界覆盖，规格 §需-001、§需-014；数据模型 §节点与端点]
- [x] CHK027 是否明确长轮次不叠加、活动节点不重复候选检测、恢复抢占候选槽及连接满额时内部健康检测的独立有界预算？[边界覆盖，规格 §需-003、§边界情况；数据模型 §工作进程与活动出口、§连接配额与事件；配置契约 §检测与重试语义]

## 非功能要求与范围控制

- [x] CHK028 是否明确业务连接、域名解析及检测跳转都受目标隧道约束，且缺少已验证出口时没有直连或系统代理环境变量回退？[安全完整性，规格 §需-005 至需-008；网络契约 §防直连规则；配置契约 §字段与默认值]
- [x] CHK029 是否明确不可信节点配置、远端推送、凭据和日志的边界，包含危险配置拒绝、敏感信息不输出及认证失败不转发的要求？[安全完整性，规格 §需-009、§需-014、§需-015；网络契约 §不可信配置；命令行契约 §控制套接字与状态字段]
- [x] CHK030 精简要求是否落实为明确排除网页、多来源、数据库、复杂评分、主动轮换及无损迁移，并说明每个必要常驻组件和有界资源的用途？[范围一致性，规格 §假设；计划 §技术背景、§复杂度记录；研究 §一、以一个可复用核心为基础]
- [x] CHK031 是否明确参考源码中可直接复用、需裁剪改造和必须补齐的能力及选择依据，避免默认全量重写，也避免未经适配就承诺原项目能力？[完整性，规格 §需-017；研究 §一、以一个可复用核心为基础；源码核查记录]

## 依赖、假设与歧义

- [x] CHK032 是否明确首版支持的系统、处理器架构、原生环境和容器模式，以及尚未验证的部署组合不能被描述为已支持？[依赖清晰度，规格 §需-011、§需-012、§假设；计划 §技术背景]
- [x] CHK033 是否完整说明部署所需权限、设备、宿主前提与安全配置的用途和失败行为，且不将关闭宿主防护作为默认部署条件？[依赖完整性，规格 §需-012、§需-013；网络契约 §Docker 契约、§无上游的直接连接]
- [x] CHK034 设计新增的公网业务目标限制、固定隧道内解析器与跳转上限，是否具有明确范围依据，并与可配置普通检测网页及用户预期一致？[歧义，规格 §需-002、§需-008、§假设；命令行契约 §SOCKS5 契约；配置契约 §字段与默认值]
