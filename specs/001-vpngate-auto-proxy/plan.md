## 容器单一环境配置增量设计（2026-10-15）

对应 US8、需-022、成-014。在 Rust 配置模块添加显式容器环境转换器，使用既有序列化和业务校验，无新依赖；固定容器路径和监听端口，不读取密码、系统代理或任意 JSON 注入。内部 `container-config` 仅输出经过校验的公开配置。入口只在无参数且 `VAP_CONFIG_MODE=environment` 时生成私有临时文件后执行普通 run；默认文件模式和显式 status 等命令不转换环境。无效模式或参数均先拒绝。

发布镜像编排覆盖文件清除构建及 JSON 挂载，保留数据卷、凭据秘密、只读根目录、能力和宿主策略；显式传入允许的配置变量，不将整个 `.env` 作为容器环境。环境变量名单由现有配置数值字段和指定文本字段组成，空值采用程序默认；列表逗号分隔、禁止空列表项、布尔仅接受 true/false、数字为无符号十进制整数。环境转换使用注入式读取器以免测试修改全局环境。文件模式保持原行为。

先完成规格及设计任务，再用转换/真实命令行拒绝测试驱动实现，最后核对编排没有 JSON 文件挂载、构建步骤及密码环境变量。环境变更使用 `docker compose up -d` 重新创建，不能用 restart 读取新的 `.env`。不重跑无关联的容量试验；实际发布镜像须按既有冻结和目标验收门槛重新构建。

## 摘要

以已有 MIT Rust 核心裁剪为基础，保留网络隔离、代理认证、配置清洗和退出清理，
删除网页、风险评分、数据库及强制上游代理。补齐直接获取节点、跨重启缓存、
每轮 20 节点的候选出口验证，以及随机多地址、默认最多 3 次、任意 2xx 成功的健康检测。
一次检测失败立即撤销活动出口并切换；所有节点不可用时保持运行并退避。
启动与恢复的待启用隧道验证后直接提升，避免先释放再重建；后台候选检测后仍释放。

本计划只完成研究与设计，不创建应用源码、部署文件或任务清单。

按数据模型删除失去归属的历史并淘汰最旧记录，不影响当前候选可用性或活动状态。
