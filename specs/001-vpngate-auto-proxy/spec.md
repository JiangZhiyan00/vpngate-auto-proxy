# 功能规格：自动节点获取、验证与局域网代理

## 用户故事八：容器单一环境配置（2026-10-15）

用户选择 Docker 部署只维护 `.env`；首次准备凭据和宿主策略后直接执行 `docker compose up -d`。原生及既有文件部署继续使用 JSON，不隐式改变其行为。

**需-022**：镜像仓库部署通过显式环境配置模式接收地区、时区、来源、旧算法兼容及现有检测/容量数字参数；启动时生成临时 JSON，复用现有严格类型与业务校验，在创建网络资源前拒绝非法配置。无值采用现有默认值，地区与检测地址使用逗号分隔；国家列表空值表示全部。容器监听、凭据路径、数据与运行目录固定为现有部署约束；不通过环境变量传递代理密码，不引入宿主代理变量读取。配置变更通过重新创建容器生效。

**验收场景**：一、仅准备 `.env` 和凭据、不创建或挂载用户 JSON，编排直接使用发布镜像；二、地区、时区、布尔及检测参数正确转换并经原有校验；三、非法地区、时区、布尔、数字或网址启动失败且不创建网络资源；四、显式文件模式和管理命令保留原行为，原生 JSON 不受环境变量影响；五、生成文件仅在容器临时目录，凭据内容不进入配置或输出。

**成-014**：上述转换回归、真实入口无网络配置生成与拒绝实验、两种安全策略编排核对通过；完整公开镜像部署仍纳入 T111/T112，不由本地测试替代。

## 澄清记录

### 会话 2026-10-10

- 问：节点较多时，每轮检测全部节点还是分批轮换？ → 答：分批轮换；每轮最多检测 20 个候选节点，数量可配置，优先从未检测或最久未检测的节点。
- 问：重启后是否保留节点列表用于来源暂时不可用时恢复？ → 答：保留节点列表及获取时间，未过期缓存可用于选择候选；重启后必须重新验证隧道与出口，不恢复历史就绪状态。
- 问：首版需要同时服务多少台设备、多少个代理连接？ → 答：以 5 台设备、合计 50 个并发连接为验收规模，暂不承诺带宽指标。

- 问：出口可用性验证普通检测地址还是实际业务服务？ → 答：只验证普通网络连通性检测地址，例如返回 204 的检测地址；不要求验证具体业务服务。

- 问：是否以 1 核处理器、1 GB 内存作为设计与验收预算？ → 答：不预设该预算，项目保持精简；具体占用通过后续实测记录，不据此宣称最低配置。
- 问：全部节点不可用时，等待重试还是退出？ → 答：保持进程运行并等待下一次重试，不因全部节点不可用而自动退出。

- 问：是否要求从头独立实现全部功能？ → 答：不要求；尽量参考已有开源项目的设计与实现，优先复用或裁剪成熟成果，不重复实现已有能力。

- 问：出口验证是否严格匹配预期状态码？ → 答：不严格匹配；支持配置多个检测地址并随机选择，可使用普通网页，最终返回任意 2xx 即成功，允许跟随跳转且不要求响应体非空。

- 问：随机检测地址失败后如何重试？ → 答：单次检测最大尝试次数可配置，默认 3 次；每次随机选择一个链接，任意一次成功即停止，全部尝试失败则本次检测失败、认为节点不通。

- 问：单次检测的全部请求失败后何时切换？ → 答：立即切换节点，不再等待连续多轮检测失败；移除旧的连续 3 轮失败阈值。

## 用户场景与测试（必填）

### 用户故事一：启动代理并供授权设备使用（优先级：一）

部署者在 Linux 上通过命令行或容器启动服务，系统自动获取并验证节点，
连接可用节点后，为本机或授权局域网设备提供统一代理地址。
使用者只需配置代理地址和访问凭据，无需自行管理隧道。

**优先原因**：提供可用的代理入口是产品的核心价值。

**独立测试**：提供一个可用的受控节点来源与节点，启动服务，
用本机和一台局域网设备访问受控目标，核对请求经过选定节点。

**验收场景**：

1. **给定**来源含有可用节点，**当**部署者按说明启动，**则**系统完成隧道与出口验证后
   才允许业务转发，并显示代理就绪、当前节点及最近验证时间。
2. **给定**没有自定义监听配置，**当**启动，**则**仅本机可以连接默认代理端口。
3. **给定**显式配置局域网监听及用户名、密码，**当**设备使用正确凭据请求代理，
   **则**请求通过活动隧道到达目标；缺少或错误凭据的设备不得转发业务流量。
4. **给定**配置了非回环监听但未配置完整凭据，**当**启动，
   **则**拒绝启用该监听，明确报告配置错误。
5. **给定**所有节点均不可用，**当**启动，**则**显示等待可用节点，按退避规则重试，
   代理请求明确失败且不得通过宿主机直连；进程保持运行，等待下次重试，
   不因等待时间长或连续无可用节点而自动退出。
6. **给定**受控活动出口正常，**当**5 台授权设备合计维持 50 个并发连接，
   **则**所有连接都能持续收发数据，后台检测不造成连接中断；
   达到配置连接上限后，新连接明确失败且不影响已有连接。

### 用户故事二：持续更新与验证候选节点（优先级：二）

部署者无需反复手动下载或测试节点。系统独立刷新节点列表、验证候选节点，
并显示端口可达、隧道建立、出口可用及结果过期等区别。

**优先原因**：公共节点状态会变化，定期验证为长期使用和故障恢复提供依据。

**独立测试**：使用含离线、仅端口可达、握手成功但出口失败、完全可用节点的受控来源，
推进检测周期，核对状态与时间；同时通过已建立代理发送持续请求。

**验收场景**：

1. **给定**上述不同类型的节点，**当**执行一轮验证，**则**只有隧道建立且出口请求成功的
   节点标记为可用，其余节点保留实际完成层次及失败原因。
   对 200 普通网页、空响应 204 和跳转后返回 2xx 的地址均判成功；
   最终返回非 2xx 或请求超时则该地址尝试失败。
   单次检测默认最多尝试 3 次，每次随机选择链接；第 1 次或第 2 次成功后不继续尝试，
   全部尝试失败时记录一次检测失败。
2. **给定**代理正在正常使用，**当**后台检测候选节点，**则**活动出口不变，
   现有请求不中断，宿主机既有路由和域名解析设置不被候选检测改变。
3. **给定**结果超过有效期，**当**查看或选择该节点，**则**结果显示过期，
   不作为当前可用证明；成为活动出口前必须重新验证。
4. **给定**来源暂时不可用，**当**刷新失败，**则**保留未过期缓存并显示缓存年龄；
   无有效缓存时不新选节点，仍独立检测已有活动隧道。
6. **给定**已缓存节点列表且服务或容器已重启，**当**来源不可用，
   **则**使用保留的获取时间判断有效期；未过期时重新验证候选后才能恢复转发，
   过期时等待来源恢复，历史成功结果不使服务直接就绪。
5. **给定**新来源列表删除了活动节点，**当**刷新成功，**则**标记其已不在来源中，
   正常隧道保持服务；断开后不得再次选择已删除节点。

### 用户故事三：出口故障后自动恢复代理（优先级：二）

使用者遇到当前出口故障时，系统停止不可用出口的转发，尝试连接其他候选节点，
验证成功后恢复同一代理入口；无需使用者修改代理地址。

**优先原因**：自动恢复减少持续使用中的人工干预。

**独立测试**：提供一个活动节点和一个可用备用候选，主动中断活动节点，
观察转发阻断、切换及恢复；再使全部候选不可用，核对等待与重试行为。

**验收场景**：

1. **给定**活动隧道明确断开，**当**系统收到断开状态，**则**立即停止业务转发并开始切换。
2. **给定**隧道仍连接且使用默认最大尝试次数，**当**一次出口检测在最多 3 次随机地址尝试后全部失败，
   或达到本次检测总超时仍未成功，**则**暂停业务转发并立即开始切换，
   不再等待后续检测周期确认；新的活动隧道验证成功前不得恢复转发。
   单次检测内某次请求失败但后续请求成功时，本次检测成功，不触发切换。
3. **给定**存在可用备用候选，**当**完成该候选的实际连接及出口验证，
   **则**恢复原代理入口；旧连接关闭，客户端可以重连，不要求已有连接无损迁移。
4. **给定**候选连接失败或出口验证失败，**当**尝试切换，**则**不向其转发业务，
   记录原因并按有界尝试与退避规则继续，始终不得回退直连。
5. **给定**活动节点健康而新候选检测结果更快，**当**后台检测结束，
   **则**保持当前节点，不为追求评分主动轮换。

### 用户故事四：用简单命令行或容器完成运行管理（优先级：二）

部署者能够查看帮助、启动服务、读取运行状态，并正常停止服务。
容器部署者能够按文档传入配置和凭据、映射端口，向局域网提供相同能力。

**优先原因**：降低部署成本，同时保持无网页管理的简单使用方式。

**独立测试**：按文档分别运行命令行和容器部署流程，完成状态查看、设备访问及停止，
检查退出后的端口、隧道与临时网络资源。

**验收场景**：

1. **给定**有效配置，**当**按帮助启动及查看状态，**则**无需网页即可看到当前节点、
   服务状态、监听地址、最近检测时间、候选汇总及最近失败或切换原因。
2. **给定**端口冲突、权限不足、依赖缺失或参数错误，**当**启动，
   **则**报告具体原因并以失败结果退出，不留下部分启动的隧道或监听。
3. **给定**受支持的 Linux 容器宿主环境，**当**按文档传入配置、授权运行权限并映射端口，
   **则**授权局域网设备可以使用代理；默认部署不得因端口映射而变成无认证公开代理。
4. **给定**服务正在运行，**当**正常停止进程或容器，**则**停止接收新请求、关闭现有连接，
   释放本服务创建的隧道、监听和临时网络规则，不删除其他程序的网络资源。
5. **给定**程序被强制终止，**当**再次启动，**则**发现并处理可识别的遗留资源，
   无法安全处理时明确失败，不覆盖其他进程的资源。
6. **给定**容器已按文档保留缓存数据，**当**重启或替换容器且节点来源暂时不可用，
   **则**仍能读取未过期的节点列表及原获取时间；缓存缺失、损坏或过期时明确提示，
   在来源恢复前不通过新节点转发业务。

### 用户故事五：按国家/地区选择节点（优先级：二，US5）

部署者指定允许使用的国家/地区，例如日本和新加坡，使候选验证与出口选择遵循同一范围。

**优先原因**：避免每次部署后人工排除不需要的地区。

**独立测试**：提供日本、新加坡和美国的受控来源，分别使用全部地区、指定地区和无匹配地区配置，检查候选及实际出口；保留完整缓存后改变配置并重启。

**验收场景**：

1. **给定**未配置地区或配置为空列表，**当**获取有效来源，**则**全部有效节点都可进入原有选择流程。
2. **给定**允许日本和新加坡，**当**刷新或恢复缓存，**则**只验证及选择这两个地区的节点；代码比较不区分字母大小写。
3. **给定**有效来源或未过期缓存中没有匹配地区，**当**启动或选择出口，**则**保持等待且拒绝业务转发，不改选其他地区或宿主机直连。
4. **给定**缓存同时包含多个地区，**当**修改允许地区并重启且来源不可用，**则**对原完整缓存应用新筛选；不刷新原获取时间，不恢复历史就绪。
5. **给定**地区列表格式非法或超过规定上限，**当**启动，**则**在创建隧道前报告配置错误。

### 用户故事六：按部署时区查看运行时间（优先级：二，US6）

部署者设置所需地区时区，运行日志和状态命令按该地区规则显示时间，无需改变宿主机时区。

**优先原因**：让分布在不同地区的服务器记录可直接用于排查问题。

**独立测试**：以日本、新加坡、纽约和悉尼的冬季及夏季时间样本核对显示偏移和同一时刻，另检查省略和非法配置。

**验收场景**：

1. **给定**省略时区，**当**查看日志和人类可读状态，**则**默认上海时区。
2. **给定**配置有效地区时区，**当**日志或人类可读状态显示时间，**则**按该地区在对应日期的偏移显示，适用时自动采用夏令时。
3. **给定**同一检测结果与缓存，**当**改变显示时区并重启，**则**机器接口及持久时间仍表示同一时刻；缓存年龄、有效期和调度预算不因显示偏移变化而改变。
4. **给定**服务器时区或容器环境时区不同，**当**存在实例配置，**则**实例配置决定显示；非法时区名称在启动前被拒绝。
5. **给定**旧状态消息没有显示时区字段，**当**新版状态命令读取，**则**按上海时区显示；不承诺旧版严格客户端可读取新版新增字段。

### 用户故事七：通过版本标签发布镜像（优先级：二，US7）

维护者配置镜像仓库和访问密钥后，推送稳定版本标签，即可获得同名版本镜像及对应完整源码材料。

**优先原因**：使 Docker 交付可重复执行，并保留每个版本的来源及验证依据。

**独立测试**：在公开的验收仓库配置专用凭据，推送合法标签，核对工作流、版本附件和可拉取镜像；另验证非法标签及前置步骤失败时不推送镜像。

**验收场景**：

1. **给定**两个公开仓库及有效凭据，**当**推送形如 `v1.0.0` 的稳定版本标签，**则**完成检查和验收后发布同名 Linux x86_64 镜像与完整源码材料。
2. **给定**普通提交、分支推送或不合法的版本标签，**当**推送到源码仓库，**则**不发布镜像；非法标签即使触发了检查也不得进入推送阶段。
3. **给定**缺少密钥、仓库配置无效、测试或分发材料核验失败，**当**执行发布，**则**失败停止且不推送镜像，不输出凭据。
4. **给定**检查成功，**当**执行发布，**则**先提供公开源码附件，再推送已经验收的同一镜像；附件包括核验摘要及明确范围的验收记录。
5. **给定**已有版本或推送途中失败，**当**恢复发布操作，**则**不自动覆盖既有附件，不移动已公开标签，不因补发旧版本更新通用最新版本标识；后续修复使用新版本。

### 边界情况

- 来源为空、不可达、重复节点、条目损坏或携带危险配置：跳过无效条目并记录原因；
  不执行远端提供的脚本或任意命令，全部无效按无可用节点处理。
- 检测目标支持非空的可配置地址列表，每次出口验证随机选择目标；
  最终返回任意 2xx 即成功，包括无响应体的 204 和普通网页的 200，允许跟随跳转。
  跳转也必须经过被验证隧道并受本次总超时约束，不能回退宿主机直连。
  单次检测最多尝试配置次数，默认 3 次，每次随机选择一个链接，任意成功即停止；
  所有尝试失败或达到本次总超时则本次检测失败。
  状态明确注明检测失败不能单独证明节点故障，也可能是检测地址不可用。
- 每轮候选验证最多处理配置数量的节点，默认 20 个；优先从未检测或最久未检测的节点，
  同优先级按稳定节点标识排序，不重复挑选同一轮中的节点。未轮到的节点保留未检测或过期状态，
  不得据此标记失败。一轮超过调度周期时不叠加下一轮，完成后在下一个调度时点继续轮换。
- 源缓存过期但活动隧道健康：维持活动出口验证和服务，不用过期缓存选择新的出口。
- 节点响应缓慢、系统恢复网络、服务重启：检测均有超时；恢复后重新验证，不沿用旧就绪状态。
- 切换时有长连接：明确关闭旧连接，由客户端重连；不声称切换无损。
- 域名请求和数字地址请求：都遵循活动隧道出口策略，隧道不可用时不得从宿主机解析业务域名。
- 请求不支持的代理命令、数据报转发或地址族：明确拒绝，不尝试其他出口或直接发送。
- 状态查询、错误输出及容器日志：不得打印密码、完整敏感配置或业务访问内容。
- 并发连接达到上限：拒绝超出上限的新连接，状态或日志说明已达到限制；
  不挤占或中断已有连接。断开连接后释放额度，后续连接可再次建立。

- 国家/地区信息只依据来源声明，不增加独立出口地理位置核验；只接受格式合法的两字母代码，未知但格式合法的代码可导致无匹配等待。
- 空筛选表示全部地区；筛选后为空与来源本身为空须有可定位的诊断。来源刷新同时失败时允许优先显示刷新错误，候选仍不得越过筛选。
- 时区只影响显示，不改变节点有效性、流量隔离或宿主机时钟；纽约与悉尼的夏令时季节相反，应分别核对。
- 发布失败可能留下已公开源码附件；不能以附件存在或构建成功推定镜像已推送。每个版本的远端发布结果单独记录。

## 需求（必填）

### 功能需求

- **需-004**：启动或切换时必须自动选择候选，优先未过期出口验证成功者，

- **需-005**：候选检测不得改变活动连接、宿主机既有路由或域名解析配置；

- **需-006**：必须持续检测活动出口；一次出口检测在配置的最大尝试次数内全部失败，

  单次检测内任意一次成功即本次检测成功，不触发切换；明确隧道断开立即切换。
  健康节点不得因新候选更优被周期性主动断开。验收见用户故事三。
- **需-007**：没有已验证的活动出口时必须拒绝业务转发，

### 关键实体

- **节点**：来源中的稳定标识、端点、连接资料、来源获取时间及是否仍在最新列表。
- **验证结果**：关联节点、检测层次、开始及完成时间、耗时、结果、失败原因与有效期。
- **活动连接**：当前节点、连接状态、最近出口验证、本次检测的已尝试次数及当前是否允许业务转发。
- **运行配置**：监听与认证、允许国家/地区、显示时区、客户端连接上限、各检测周期、超时、检测并发、退避及检测地址列表。
- **版本交付**：稳定版本标签、目标镜像仓库、镜像身份、完整源码材料及摘要、明确环境与范围的验证结果；不含发布凭据。
- **运行事件**：启动、停止、刷新、验证与切换发生时间、关联节点及原因，不含访问内容或密码。

## 成功标准（必填）

### 可衡量结果

所有时间和稳定性标准均使用受控环境与默认参数验收，
不以公共节点的实时可用性决定通过与否；真实公共节点试验另外记录时间、环境和结果。

- **成-001**：在来源 5 秒内返回、首个候选 30 秒内完成连接且 10 秒内通过出口验证的条件下，
  启动后 60 秒内可由授权设备经代理完成首个请求；首个待启用隧道只完成一次建立与出口验证，
  验证成功后直接启用，不插入第二次连接或重复验证。
- **成-002**：至少覆盖离线、仅端口可达、隧道成功但出口失败、出口可用、结果过期五类节点，
  所有状态分类正确率为 100%。在固定的 45 个非活动候选、全部单次检测都能在周期内完成的
  环境中，前两轮分别覆盖 20 个此前未检测的节点，第三轮优先覆盖剩余 5 个，
  三轮累计覆盖全部 45 个候选，未轮到节点不误记失败；
  每轮数量和并发均不超过配置，长期运行不遗漏候选。
- **成-003**：活动出口故障、存在一个可用且未过期的备用候选、其连接与出口验证合计不超过
  40 秒时，120 秒内恢复同一代理入口的新请求；故障、等待和切换期间的
  受控流量观测中，宿主机直连的代理业务数据与业务域名解析请求均为零。
- **成-004**：活动代理连续运行 30 分钟，每秒完成一个受控请求，期间至少执行两轮候选检测；
  因候选检测引发的请求失败、活动出口切换和宿主机既有网络配置改变均为零。
- **成-005**：使用同一配置进行命令行与容器部署，两种方式均通过授权设备成功访问、
  错误凭据拒绝访问、默认不向局域网开放、故障阻断及正常停止验收；
  两种部署方式均通过来源不可用时利用未过期缓存重启恢复的验收，
  容器替换后保留原缓存获取时间，过期或损坏缓存均不用于新节点选择。
- **成-006**：全部启动失败和正常停止验收场景均不遗留服务监听或本服务创建的临时网络资源；
  正常停止 15 秒内完成，已有宿主机网络设置保持不变。
- **成-007**：使用说明覆盖从配置到状态查看和停止的完整路径，
  验收者无需网页或修改源码即可完成部署及排查所列故障；所有规定状态字段均可查看。
- **成-008**：连续 30 分钟无可用节点的受控试验中，重试遵守退避上限，
  每轮数量与检测并发不超过配置；在恢复节点属于下一轮待检测批次的前提下，
  服务能够在下一次重试发现该节点并重新验证后恢复使用。

- **成-009**：在受控可用出口与足够带宽环境中，5 台授权设备各维持 10 个连接，
  合计 50 个并发连接持续 30 分钟，每个连接每 10 秒完成至少一次小数据往返，
  期间至少完成两轮候选检测；无服务异常退出、因容量或候选检测导致的连接中断。
  第 51 个连接明确失败且不影响前 50 个；关闭其中一个后，新连接能够成功建立。
  命令行与容器部署分别满足此标准，不以公共节点带宽衡量通过与否。
  验收记录应包含测试环境、空闲和上述负载下的处理器及内存占用，
  不以未经实测的固定硬件预算作为最低配置声明。

- **成-010**：受控出口检测覆盖首次成功、失败后成功、全部失败、跳转后成功、空响应成功、
  非成功状态及总超时：首次成功只请求 1 次，第二次成功只请求 2 次，
  前两次失败且第三次成功不切换；3 次均失败后不等待下一检测周期就开始切换。
  配置最大次数为 1 或 5 时分别遵守对应上限；最终响应为 200 或 204 均通过，
  请求跟随跳转仍走目标隧道，总超时到达后不再发起下一尝试。
  多地址列表的每次选择均来自配置列表，单地址列表允许重复尝试。

- **成-011**：含日本、新加坡、美国的受控来源在指定日本和新加坡时，所有进入选择流程的节点均属于指定地区；省略或空筛选时三个地区都可进入流程。修改筛选后使用原完整缓存重启，结果符合新配置且获取时间保持不变；无匹配且无健康活动出口时新增出口及业务转发均为零；此前合规选出的健康活动出口遵循来源删除后的原维持规则，不因候选视图为空主动断开。
- **成-012**：日本、新加坡、纽约及悉尼各自冬季和夏季的八组时间样本显示偏移全部正确，转换前后表示同一时刻；非法名称被拒绝，旧配置及旧状态仍采用默认上海。改变显示时区不重置缓存获取时间或改变有效期判断。
- **成-013**：一次合法稳定版本标签推送后，维护者可在目标仓库拉取同名、架构正确的镜像，并取得该版本公开的完整源码材料、摘要及验收记录；镜像身份与验收记录一致。普通提交、非法标签和前置门槛失败场景不产生镜像推送；真实发布结果须留有证据。

## 假设

- 首版要求苹果系统与 Linux 原生服务端，并交付可用的 Linux Docker 部署方式；
  不承诺其他宿主系统的容器联网行为，其他设备只要能够连接代理即可作为客户端。
- 用户具备部署服务和配置局域网访问的权限，服务环境能够获取节点来源并连接节点；
  不要求已有上游代理，不把解决来源封锁或宿主机本身断网纳入本期。
- 首版以 VPNGate 提供的 OpenVPN 节点为隧道来源，仅包含 SOCKS5 流式连接、
  IPv4 业务目标及代理端域名解析；数据报转发、IPv6、额外代理协议及其他节点来源不在范围。
  这是简化首版的范围基线，未实现的能力必须明确拒绝。
- 一个实例服务一个活动出口，不提供多出口分流、复杂质量评分、无损长连接迁移、
  网页、用户管理系统、定时主动轮换或运行中热更新。
- 首版局域网访问采用一组用户名、密码；不新增账号注册与权限管理。
  需要更精细的来源限制时由部署网络控制，不替代服务自身认证要求。
- 项目以精简运行和低维护成本为目标，不预设 1 核处理器、1 GB 内存的固定预算；
  技术规划须说明常驻组件的必要性，资源占用在后续验收中实测记录。
  不能以简化为由移除已确认的出口验证、隔离、故障阻断或访问认证要求。
- 检测参数为可调整的首版基线；隧道实现、隔离方式、语言、依赖、具体镜像与发布方式，
  以及检测地址在技术规划阶段确定，并验证满足本规格。
- 必须结合已有开源项目的设计与实现，优先复用满足需求、资源目标和许可条件的现成代码、
  组件或实现方案，避免从头重复实现。允许基于已有项目裁剪改造，也允许按模块组合复用；
  具体基础项目在源码核查后由技术规划确定，不预设全量重写。
  复用时记录来源版本、改动及归属，并通过章程规定的许可证和关键行为验证门禁；
  参考项目宣称的能力不能替代本项目的实际验收。
- 出口可用仅表示通过配置的普通网络连通性检测，不保证特定网站或业务服务可访问。
- 指定参考范围包含 [节点代理网关](https://github.com/zhaxg/vpngate2proxy)、
  [节点检测与调度项目](https://github.com/illria/gatevpn)、
  [隔离隧道代理项目](https://github.com/Uber-Eins/vpngate2socks) 和
  [轻量代理网关](https://github.com/wanchangkongyi/vpngate-gateway)。
  技术规划须记录核查版本、可复用能力、差距和选择依据，而不是只引用项目说明。
  已有[源码核查记录](../../docs/reference-review.md)可作为技术规划输入。
- 自动发布以两个公开仓库、维护者有权限配置 GitHub 密钥及变量、可用的远端构建环境为前提；当前仅发布已验收范围内的 Linux x86_64 镜像。每版本受控短试不等同于重新完成三十分钟容量验收。
- 公共节点由第三方运营，不承诺匿名性、持续可用性或应用层端到端保密性。
