# 核心选择规则需求质量检查清单：节点综合优选与故障恢复

**目的**：审查核心选择需求的完整性、清晰度、一致性、可衡量性及场景覆盖。
**创建日期**：2026-10-22，上海时区。
**功能规格**：[节点综合优选与故障恢复](../spec.md)
**关联设计**：[实施计划](../plan.md)、[选择契约](../contracts/selection.md)、[数据模型](../data-model.md)。
**范围**：按用户选择，仅审查综合评分、首次连接、故障恢复、冷却、跨轮遍历和后台探索。
**深度与使用时机**：标准深度，供审阅者在规划完成后、任务拆解前使用。

**说明**：本清单由需求质量检查流程生成，每项审查文档是否充分表达要求。
**审阅责任**：新增条目全部保持未勾选；只有审阅者判定对应需求质量标准满足后，才可标为已勾选。
**勾选含义**：已勾选表示需求质量审阅通过，不表示程序已经实现或功能验收通过。

## 需求完整性

- [x] CHK001 规格是否完整区分评分、速度、延迟、会话数和运行时长的含义，并明确来源指标只能决定尝试优先级？[完整性，规格§需-001至需-005]
- [x] CHK002 规格是否分别定义首次连接、故障恢复和后台检测的候选范围、优先次序与并发约束？[完整性，规格§需-007、需-008、需-011、需-018]
- [x] CHK003 规格是否明确定义跨轮遍历的开始、完成、重开及成功结束条件，并区分“轮次”和“寻找出口”？[完整性，规格§需-019；数据模型§五]
- [x] CHK004 规格是否同时定义质量配额和探索配额，以及候选不足、同轮去重和配额补足要求？[完整性，规格§需-011、需-012；选择契约§三]

## 规则清晰度

- [x] CHK005 五项固定权重是否明确为评分30%、速度35%、延迟15%、会话数10%、运行时长10%，且与不提供自定义权重入口的范围一致？[清晰度，规格§需-003]
- [x] CHK006 需求是否明确相对排名的统计总体，以及活动节点、冷却节点和已移除节点是否参与该总体？[清晰度，规格§需-002；选择契约§一]
- [x] CHK007 分项评分要求是否明确定义优劣方向、并列、仅一个有效值、全体相同及运行时长封顶条件，足以得到唯一结果？[清晰度，规格§需-004、需-005；选择契约§一]
- [x] CHK008 未知值、非法值和零值的分数要求是否逐项明确，且说明未知项是否参与名次、是否重新分配权重？[清晰度，规格§需-006；选择契约§一]
- [x] CHK009 总分相同时的有效项数、最近尝试时间和稳定标识优先次序是否完整，未尝试与相同尝试时间的含义是否明确？[清晰度，规格§需-006；选择契约§一]
- [x] CHK010 “近期成功”和“完整验证失败”是否有明确的有效期、配置归属及计次边界，能够区分内部重试、取消和失效结果？[清晰度，规格§需-008、需-009、需-019；数据模型§四]

## 需求一致性

- [x] CHK011 首次连接“高分优先派发”与“先验证成功者先启用”的要求是否一致，且明确不保证最终启用最高分节点？[一致性，规格§用户故事一、需-007、标-001]
- [x] CHK012 恢复场景中的近期成功优先是否明确限定在本次遍历尚未尝试的可派发节点内，避免与未尝试优先发生冲突？[一致性，规格§需-008、需-019、标-002]
- [x] CHK013 轮次顺序冻结与派发前成功记录到期的要求是否有一致解释，区分历史排序依据与当前可用证明？[一致性，规格§需-008、需-013；选择契约§三]
- [x] CHK014 “冷却到期一秒内更新资格”、整轮失败退避和后台检测间隔之间的优先关系是否在规格与选择契约中一致？[一致性，规格§需-010、需-016、需-019、标-003；选择契约§五]

## 验收标准质量

- [x] CHK015 首次并发竞速与恢复逐个验证的成功标准是否能客观区分派发顺序、完成顺序和最终启用结果？[可衡量性，规格§标-001、标-002；选择契约§三]
- [x] CHK016 冷却要求是否给出初始时长、连续失败增长、最大值、成功清零和到期边界，使不同审阅者得到相同结论？[可衡量性，规格§需-009、需-010、标-003]
- [x] CHK017 二十一个节点的跨轮验收是否明确前二十个失败、冷却结束、第二轮选择及允许重新遍历的前提？[可衡量性，规格§需-019、标-008]
- [x] CHK018 探索覆盖的轮数上界是否列明候选池不变、无冷却及检查可完成等适用条件，且覆盖单名额交替情形？[可衡量性，规格§标-004；选择契约§三]

## 主要与替代场景覆盖

- [x] CHK019 首次连接从前列候选失败到继续选择后续节点的需求是否完整，且不会在尚有未尝试候选时重新优先选择失败高分节点？[覆盖性，规格§用户故事一、需-019]
- [x] CHK020 恢复需求是否覆盖没有有效成功记录、成功记录过期以及多个成功时间相同的候选选择？[覆盖性，规格§用户故事二、需-008、需-006]
- [x] CHK021 已有健康出口时的选择需求是否明确后台成功候选不触发换线，并区分首次或恢复成功后原轮剩余任务与下一完整后台轮？[覆盖性，规格§需-012、标-006；选择契约§二、三]
- [x] CHK022 单轮只有一个名额时，需求是否明确质量与探索交替的起点，以及空轮是否推进交替状态？[覆盖性，规格§需-011；选择契约§三]

## 异常与边界覆盖

- [x] CHK023 零候选、仅一个候选和所有候选冷却的选择要求是否有明确等待、重新参与及禁止提前重试的边界？[边界覆盖，规格§边界情况、需-010、需-019]
- [x] CHK024 候选派发前被删除、配置变化或进入冷却时，需求是否明确其是否占用配额、如何补位及是否允许改变本轮排名？[边界覆盖，规格§需-010、需-013；选择契约§二]
- [x] CHK025 寻找出口期间仅更新指标、新增节点、删除节点和配置变化的需求是否分别说明对已尝试标记及遍历完成条件的影响？[边界覆盖，规格§边界情况、需-019]
- [x] CHK026 取消、迟到结果和重复完成通知的需求是否明确不重复占用轮次额度、不重复累计失败且不错误推进遍历？[边界覆盖，规格§需-009、需-019；选择契约§二；数据模型§四]
