# 数据模型：节点综合优选与故障恢复

本设计只增加来源数据及运行期调度状态；现有节点端点、净化配置、隧道资源、控制帧和业务访问控制继续使用原模型。

## 一、来源质量指标

在 VpnNode 中新增 `quality: SourceQualityMetrics`，使用默认值兼容旧缓存；结构及各可选字段缺失时为未知。保留拒绝未知字段。指标所属时间为现有 `source_fetched_at`，与快照获取时间一致。

| 字段 | 类型 | 单位和约束 |
| --- | --- | --- |
| score | 可选无符号64位整数 | 来源评分，无量纲，零有效 |
| speed_bps | 同上 | 比特／秒，零未知 |
| ping_ms | 同上 | 毫秒，零未知 |
| sessions | 同上 | 会话个数，零有效 |
| uptime_ms | 同上 | 毫秒，零有效，评分时先截到86,400,000再计算 |

来源单项解析失败只设该项未知。缓存写出仅含规范化数值或空值；读入质量项中的错误数值类型、负值或超范围数值同样规范化为未知，未知字段和破坏节点身份的内容仍拒绝。质量结构缺失或为空对象兼容；整个结构为空值、数组或其他错误形状时拒绝，不降级节点安全校验。字段、模式与体积边界见[来源契约](contracts/source-diagnostics.md)。

## 二、节点配置身份

`NodeKey = (NodeId, profile_digest)`；NodeId仍由公网地址、端口与传输协议决定。指标变化不改变任一身份。下列运行期数据均以 NodeKey 为键，禁止只按地址继承配置相关的成功或失败。

相同配置刷新保留尝试时间、冷却与遍历。首次出现的新键未尝试，不继承另一键历史；旧键离开时删除完整候选资料与旧成功资格，仅保留尚受保护的最小历史。同键重现（包括切换配置后切回）恢复自身原冷却及当前遍历标记，不恢复旧成功资格。健康活动出口可继续持有旧身份，但不作为新候选。

离开来源的最小历史只含配置键、连续失败数、原冷却期限、当前遍历标记及必要尝试时间，不含配置正文。冷却结束且不再属于当前遍历已尝试集合时可回收；遍历结束或寻找成功释放对应遍历标记，未结束冷却保留。当前与历史身份并集合计最多40,000条，同键重现复用原记录。新增前先回收无保护记录，仍需超限则报告历史容量不足并按现有受控停止与资源回收路径退出，不淘汰受保护记录。不持久化历史，不扩大来源20,000节点上限。

## 三、冻结评分

`ScoreMicros`：零至100,000,000的无符号整数，单位为百万分之一分。权重常量依序30、35、15、10、10。中间乘法用扩宽整数，统一四舍五入，避免溢出和浮点平局偏差。

`NodeAssessment` 包含 NodeKey、来源时间、五项规范化指标、有效项数量、五个分项分、总分、最近尝试时间、冻结的有效近期成功时间。排名按[选择契约](contracts/selection.md)，正常范围及全部缺失均有定义。

当前轮评定不可变；新快照只更新下轮评分输入。成功优先时间在 Catalog::start_attempt 清除检测前捕获。

## 四、完整尝试与失败冷却

`AttemptDisposition` 区分成功、节点失败、取消、失效结果、系统致命失败。最终完整结果只提交一次，包含尝试标识、NodeKey和结束时间；检测层次仍保留在既有 CheckResult 中。

`NodeRuntime` 包含连续失败计数、单调时钟冷却期限、仅用于展示的墙上截止时间、最近尝试序号与时间。失败计数饱和处理，冷却为30乘2的连续失败次数减一次方，上限300秒；避免按无界次数移位。成功真实出口验证清零；活动故障计一次，取消和失效不增加。内部候选重试不单独提交失败。

状态流：可参与 → 已派发 → 成功或节点失败；失败 → 冷却 → 可参与。取消 → 释放工作槽且不标记遍历已尝试。致命系统或清理错误 → 沿用停止与回收路径。

## 五、寻找出口会话与遍历

`SearchSession` 包含递增会话标识、用途（首次或恢复）、当前遍历序号及 `attempted: Set<NodeKey>`。`in_flight` 独立记录，防止重复派发；仅完整结束的当前配置尝试进入 attempted。

- 进程启动首次寻找，活动故障开启恢复寻找；冷却记录独立保留，不因新寻找清除。
- 生成下一轮时只选当前遍历未尝试且符合来源、筛选、配置与冷却条件的节点。
- 当前存在且符合静态筛选的节点全部已尝试，且无当前遍历在途任务时，才能清空 attempted 并开始下一遍历。
- 未尝试但冷却的候选阻止提前开始下一遍历；删除或筛选失效节点不阻止完成。
- 来源首次出现的配置身份引入新键；仅刷新指标不重置进度；当前遍历已尝试键重现仍已尝试，删除不参与遍历完成判断。
- 出口启用结束寻找；重启不恢复会话或进度；后台探索不使用该集合。

## 六、轮次与后台公平性

`RoundPurpose` 为首次、恢复、后台；`RoundPlan` 包含轮次标识、来源时间、冻结候选与备用顺序、质量与探索集合、最多实际派发数、运行及完成计数。首次和后台并发不超过现有配置，恢复为一。

轮次最多派发 min(配置批量, 当前可派发候选数)；无效或冷却的排队条目不占实际配额，使用冻结备用条目补位。备用表最多来源节点数，空间有界。

`RoundPlan` 保存本轮开始时刻和固定预刷新窗口截止时刻（本轮开始＋候选检测间隔），到期时刻小于等于截止的成功记录进入预刷新层。实际下一轮仍从本轮结束后等待间隔。

`BackgroundState` 记录单名额质量／探索交替状态；探索使用共享最近尝试时间，未尝试优先且同时间按稳定节点标识排序。先预留探索集合再挑质量集合，避免重叠；实际派发顺序质量在前、探索在后。轮次成功转为有活动时保留原轮计划，只调整剩余任务角色与并发，不重分配名额。

## 七、时间与状态诊断

调度期限用单调时钟；外部显示用现有时区转换墙上时间。分别保留来源重试、失败轮次退避、冷却资格及后台轮次间隔，不混用。资格到期一秒内更新，实际派发还受该用途其他门槛限制。

新增 `SelectionDiagnostic` 类型化事件承载轮次、用途、权重、单节点评定、层级、冷却与遍历原因。不持久化完整排行榜，不扩展 StatusSnapshot 和 CandidateSummary，不扩大64 KiB控制帧。事件字段与白名单见[诊断契约](contracts/source-diagnostics.md)。
