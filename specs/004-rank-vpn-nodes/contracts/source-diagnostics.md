# 来源、缓存与诊断契约

## 一、来源格式

保留现有十五列逗号分隔列表及其严格表头，不增加来源或网页抓取。五项列位置从零开始分别为评分2、延迟3、速度4、会话数7、运行时长8；连接配置仍为14，地区短码仍为6。

规范化名称分别为 score、ping_ms、speed_bps、sessions、uptime_ms。网络字段去首尾空白后只接受无符号十进制整数；空白、负数、小数、正号、非数字与超过64位范围均记未知，速度零和延迟零未知，其余零有效。未知质量字段不改变有效节点的接受统计，不使来源整批失败。表头、行数、响应、编码、配置大小、端点与净化规则保持现有拒绝语义。

同端点同配置重复行保留第一条有效配置行的整组指标；同端点不同配置冲突仍整节点排除。不逐项取最佳值合成不存在的来源记录。

## 二、来源缓存

现有 nodes.json 根与节点安全字段不变，模式版本仍为1，节点新增可选 quality 对象；对象内五项可选数值，字段缺失或字段空值为未知；quality缺失或为空对象可读，quality本身为空值或数组则拒绝。序列化写出规范化整数或空值；缓存读入单项格式错误、负值、溢出按未知处理，未知字段与整个对象形状错误仍安全拒绝。节点 source_fetched_at 作为唯一指标时间，必须与快照获取时间一致。

新程序必须读入缺少 quality 的有效旧缓存，全部指标未知。旧程序拒绝带 quality 的新缓存属可接受降级行为，部署说明必须说明降级且来源不可达时可能暂时无节点，不能称双向兼容。

保持缓存来源匹配、有效期、未来时间拒绝、普通文件、私有权限、无符号链接、32 MiB、最多20,000节点和原子替换。不得把质量对象作为忽略配置摘要、安全校验或文件边界的理由。额外字段使快照超限时记录缓存写入失败，沿用原错误处理，不扩容。

checks.json 继续只存有界检测诊断；不恢复运行期成功资格、冷却或遍历。历史归档不重写。

## 三、外部命令与状态

不新增命令或配置权重入口。固定权重随本功能版本交付，既有候选并发、批量、检测间隔、有效期、重试、日志等级与时区配置继续有效。

现有命令保持原契约：

```sh
vap status --runtime-dir /run/vap --json
vap status --runtime-dir /run/vap --check-ready
vap stop --runtime-dir /run/vap
```

StatusSnapshot、CandidateSummary的现有字段结构和就绪退出码不变；不添加完整榜单，控制帧仍最多64 KiB。详细选择解释通过下述既有日志通道获取，不能用 available 数量表示来源高分节点数。

## 四、选择诊断事件

新增调试级别的类型化 selection_assessed、selection_dispatched、selection_skipped 事件，复用现有 logging::write 和有界队列。每事件只含单节点，不传出完整连接配置。日志等级低于调试级别时不输出这些详细事件，现有普通等级活动提升、故障与状态变化事件继续存在。

| 字段组 | 内容 |
| --- | --- |
| 标准事件 | 事件类型、等级、时区时间、服务状态、节点标识、可选工作标识 |
| 轮次 | round_id、search_id（后台为空）、traversal_id（后台为空）、purpose、source_fetched_at、policy_version |
| 规则 | 五项固定整数权重，策略版本初始1 |
| 质量 | 五个规范化数值或空值、未知项、五项 score_micros、total_score_micros、valid_count |
| 优先依据 | 质量或探索名额、近期成功层级、冻结的成功时间和尝试时间 |
| 运行状态 | 连续失败次数、冷却截止时间、是否本遍历已尝试、最早恢复资格时间 |
| 原因 | 固定枚举：quality_quota、exploration_quota、recent_success、cooldown、already_attempted、not_present、profile_changed、active_node、source_expired、round_backoff、cancelled、history_capacity_exceeded |

内部枚举标识可用于机器解析，人类说明使用中文固定文案，禁止直接输出远端字符串。来源中已删除或配置失效的条目可保留原轮冻结质量信息，但必须明确标记失效，不能暗示仍可提升。无分数可用的失效事件允许质量组为空。

历史容量不足必须使用固定错误类别 history_capacity_exceeded 和固定中文说明，禁止拼入节点配置；即使调试明细关闭，也要通过现有错误通道明确报告，随后受控停止和回收。该运行期历史不写入来源或诊断缓存。

每个完整轮次对当前排名总体最多生成每节点一条评定事件，派发生成一条，跳过仅在该轮首次遇到或原因变化时生成，不在每次控制循环重复刷屏。总体最大20,000，不保留无限期诊断集合；拥塞时沿用现有丢弃和摘要机制，绝不阻塞派发、健康检测或回收。数字字段有界，单事件编码不得超过现有1,048,576字节单行上限；以最长身份和时间字段测试。

禁止日志包含来源配置正文、私钥、代理用户名或密码、未经净化的远端消息、完整来源响应或任意错误原文。不得通过绕过 safe_reason 输出自由文本；专用类型化事件必须走与既有日志同样的等级、限额与脱敏审查。

## 五、验证条件

- 新旧缓存正常往返；非法质量项降级，未知字段和安全字段篡改仍拒绝；文件边界保持。
- 来源只改质量字段时节点标识和配置摘要不变，下一轮分数更新，本轮不变，冷却和遍历不丢失。
- 调试事件完整携带单节点可核算依据，普通等级无明细刷屏，敏感标记注入后日志不含标记。
- 输出拥塞不拖延故障撤销、提升或退出；状态响应保持64 KiB以内且无全候选榜单。
