# 数据模型与命令身份

本功能不新增节点或业务数据实体，沿用[既有模型](../001-vpngate-auto-proxy/data-model.md)。下列为本次需要保持一致的交付和接口身份。

## 产品命令目标

| 属性 | 约束 |
| --- | --- |
| 公开可执行名称 | 固定 vap，唯一产品命令 |
| 项目包及库身份 | 保留 vpngate-auto-proxy / vpngate_auto_proxy |
| 源码入口 | 保留现有 src/main.rs |
| 公开操作 | run、status、stop、help，以及帮助/版本选项 |
| 内部操作 | 保留既有名称和授权要求，不在公开帮助中展示 |
| 旧名兼容入口 | 新交付不存在；历史包及用户备份不回写 |

构建目标、帮助中的用法名称、安装文件名、容器执行路径及验收程序定位都必须指向同一新目标。

## 帮助请求

请求可为总览或一个公开子命令。总览和 run/status/stop 详情成功返回中文说明与退出状态 0；无效或隐藏目标返回参数错误 2。该请求不读代理配置，不进入实例状态机、不创建缓存或网络资源。版本查询同样在服务初始化前结束，版本取程序实际包版本，不取外部镜像标签。

## 既有受保护程序安装记录

继续使用 format_version、version、binary_path、binary_sha256、system_libraries。新记录的 binary_path 文件名必须是 vap，并与现有固定父目录、版本加摘要目录和真实执行路径一致。字段及记录版本不为改名任意升级；旧 basename 的记录不能作为新程序的授权记录。

校验继续包括管理员归属、不可被普通用户写入、文件权限、摘要、固定系统加载库及无跳转路径；basename 改名不削弱任何一项。原有目录的记录仅作旧材料保留，不自动迁移为新记录。

## 安装状态与冲突

Linux 生产安装的 UID/GID、权限、路径、源快照及并发约束以[确定性规则](contracts/deployment.md#linux-生产安装的确定性规则)为准；普通用户开发目录测试不能充当该规则的真实通过证据。

- 无入口、目标目录满足安装要求：无覆盖安装成功后进入新入口可用状态。
- 已有无关文件、链接或未知归属：报冲突，安装前后原节点、内容和目标不变。
- 已有本项目旧公开入口：停止相关实例并证明归属后，由明确升级步骤移除旧入口，再安装新入口；不自动切换正在运行的实例。
- 任一步失败或归属不明：保持拒绝安装/升级，不清理其他项目资源。并发安装只能有一个新入口提交成功。

## 旧入口退休证明材料

这是升级操作的运维证据，不是新增业务数据，也不是由新安装命令自动创建的旧历史。证明由可信旧安装记录、对应发布/构建材料、实例已停止并回收结果，以及本次节点设备号/inode/元数据/摘要快照组成。记录至少关联项目身份、版本、旧公开绝对路径、程序摘要及材料来源/摘要；缺失或不匹配时退休状态为拒绝，节点不变。

退休状态依次为未审计、归属已核验、相关实例回收已确认、节点复核通过、旧公开入口已移除。任一步失败停留在拒绝/未完成状态，不切换正在运行的实例。只有旧入口退休与新安装都完成，才报告项目管理升级完成；用户手工保存的旧程序与历史受保护版本不属于该清理集合。详细允许和拒绝条件见[退休证据契约](contracts/deployment.md#旧公开入口的归属与退休证据)。

## 保持不变的实体与状态

配置字段、环境变量、凭据文件、节点缓存、状态 JSON、实例/代际/消费者身份、租约及网络资源标识均保持原含义。run/status/stop 继续使用原有状态转换、退出码和清理顺序；命令名称不是实例身份，也不能据此确定应终止或删除的资源。

2026-10-16 实施核对：上述产品、帮助及受保护记录身份已与产物一致；Linux 退休采用部署契约明确的受保护安装/材料/停止证明 JSON，并另行核对内核消费者。没有可信历史记录的部署仍拒绝自动退休，不新增业务实体。
