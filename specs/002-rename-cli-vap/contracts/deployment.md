# 构建、安装与发布契约

对应需-001、需-003、需-008—需-010。2026-10-16 已按本契约实施，Linux 独立管理员容器安装回归、本地 Docker 及分发材料核验通过。苹果受保护安装只完成普通组件回归；目标原生及新镜像强制策略验收仍独立保留，不能据实现范围宣称全部平台通过。

## 构建与原生安装

- 唯一产品二进制目标及文件名为 vap，库和包名保留；普通构建、安装及测试不能同时交付旧名产品。
- Linux 安装按当前部署文档明确的目录进行；先检查 PATH 内已有 vap 及目标节点，再采用禁止覆盖的安装步骤。未知文件、符号链接、内容或归属均报冲突，不能使用强制覆盖安装参数。受控并发安装只能有一个提交成功。
- Linux 生产安装步骤由 scripts/install-vap.py 封装：核验选定源文件和目标目录归属，在同目录暂存，再排他发布目标；失败仅清理本次暂存。必须包含既有 PATH 同名冲突预检，不能仅检查目标目录。Cargo 指定二进制安装仅用于隔离目录的构建/开发验证，不以同包重装行为代替不覆盖保证。无需新增后台安装服务或全局清理器。
- 苹果受保护安装保留固定父目录及版本摘要子目录，新文件名改为 vap；安装及记录核验仍为不覆盖原子提交、管理员归属、固定路径、模式、摘要及系统库核对。普通 cargo install 不能替代正式受保护安装。
- 苹果安装完成后使用返回的已核验程序所在目录配置 PATH，直接运行 vap；不创建指向旧名程序的别名、包装器或兼容链接。正式子进程继续使用核验后的真实绝对路径，不搜索 PATH。
- 升级前停止相关实例，若本项目曾管理旧公开入口，只在证明归属后显式移除。没有归属材料时停止升级并说明原因；不删除用户备份、未知同名程序或历史受保护版本目录。新安装不自动接管旧实例。

### Linux 生产安装的确定性规则

1. 生产安装仅接受 Linux 且实际用户与有效用户均为 UID 0；低权限调用拒绝。默认目标为 `/usr/local/bin/vap`，可显式指定绝对安装目录，不能含 `.`、`..` 或符号链接分量，不自动创建或修正目标父目录。
2. 目标目录必须已存在、UID/GID 均为 0、权限恰为 `0755`；到根目录的祖先必须均为 UID 0、不可被组或其他用户写入、允许其他用户搜索且没有特殊权限位。任何目录分量不符即拒绝；不因某个目录有粘滞位而放宽生产规则。
3. 选定源必须为绝对无跳转路径下的独立普通文件，拒绝源文件及路径分量中的链接；链接数必须为 1，大小为 1 字节至 64 MiB，不得带设置用户身份、设置组身份或粘滞位，不得被组/其他用户写入。源 UID 只允许 0 或管理员调用环境中明确的非零 SUDO_UID；无 SUDO_UID 或 SUDO_UID=0 时只允许 0。0 是管理员通过 sudo 调用时的有效身份值，不增加任何其他源属主；空值、负值、前导零或非数字值拒绝。该环境字段仅限制可选源属主，不能授权目标目录或代替摘要校验。
4. 预期摘要须由调用者依据明确选定的发布/构建材料提供，格式为 64 位小写十六进制 SHA256。打开源时不跟随链接，从同一已打开文件读取、核验元数据及计算摘要；校验后的快照是唯一写入来源，不在写入阶段按原路径重新读取。不执行候选程序以判断其身份，不以摘要代替来源审核。
5. 显式安装目录和 PATH 中的每个目录都检查名为 vap 的节点；已有普通文件、目录、可执行文件、链接或悬空链接均拒绝，不以是否可执行区分冲突。PATH 中空项或相对目录拒绝；PATH 目录的链接仅在链接链由 UID 0 管理、最终目录链满足上述 root/不可被组或其他用户写入的约束时允许规范化，按实际目录身份去重后检查，不执行其中程序。未知属主、可替换链接及无法解析的目录拒绝并报告，不能静默忽略。显式安装目录仍禁止链接；安装或升级不改写 PATH。
6. 安装使用经核验的目录描述符完成暂存及排他发布，发布前复核目录身份；最终 vap 的 UID/GID 为 0、模式为 `0755`、摘要等于选定值。不继承源的扩展属性、访问控制列表或文件能力；失败仅回收本次已登记暂存节点，不能删除已存在或被替换的目标。提交后复核最终文件，清理本次暂存后链接数为 1。
7. 新安装从不覆盖已有 vap，包括已有本项目同名程序；重复安装也报冲突。并发尝试安装同一新目标时只允许一个提交成功。原生升级必须先按下方规则确认旧入口已退休，再执行无覆盖新安装。

这些规则仅适用于 Linux 生产安装。普通用户的隔离构建/开发安装不是生产安装；测试可对纯校验组件注入元数据，但不能向生产入口增加跳过属主、权限或摘要校验的参数。真实 UID/GID、权限、并发及冲突测试在无网络的独立 Linux 管理员测试环境或容器内执行，不操作开发宿主的系统目录。

### 旧公开入口的归属与退休证据

旧入口退休是单独明确执行的升级步骤，不是新安装的隐式副作用，也不扫描磁盘按文件名批量清理。

- 必须提供此前可信安装流程留下的归属记录，关联项目身份、版本、旧入口绝对路径、二进制 SHA256，以及原发布/构建材料的来源和摘要；只有文件名、UID 0、版本输出或用户手填的文件摘要均不足以证明安装归属。记录及所在目录链须由 UID 0 管理、不得被组/其他用户写入，记录是无链接的独立普通文件。
- 记录中的旧入口仅允许 basename 为 `vpngate-auto-proxy` 的公开程序路径；任何受保护版本摘要目录、数据目录或用户备份均排除。当前入口必须为 UID/GID 0、模式 `0755`、链接数 1 的普通文件，路径无链接/跳转分量，实际摘要和完整路径必须与归属记录及选定旧发布材料一致。
- 记录不足、材料摘要不符、同名但不同内容、未知/悬空链接或归属不明时拒绝退休，原节点不变。此前没有可信安装记录的手工部署不自动视为项目管理的旧入口；保持文件不动，报告需由管理员另行核实，不补写记录冒充历史归属。
- 执行者需先按原管理入口正常停止相关实例，保存其回收完成及实例归属记录；没有可确认的停止/回收结果时不退休。不得凭 PID 或旧命令名推断实例已退出，不发送额外终止信号来获得证明。
- 退休审计先以无链接打开取得设备号、inode、类型、属主、权限和摘要快照，删除前核对目标目录及节点仍是同一身份；任何变化停止处理。仅移除显式选定且已证明归属的旧公开节点，保留归属记录、原发布材料、受保护旧版本目录和用户备份；成功后再执行新安装，失败不声明迁移完成。
- 回归必须包含合法旧入口退休成功、缺失/伪造/可写记录、错误版本材料、节点/目录替换、链接/多重链接、存活或未知消费者，以及无关命令/备份保留。新入口存在而旧入口未获确认退休时，只能报告新安装结果，不能报告项目管理的升级完成。

## Docker 与部署工具

### 实现的退休证据格式

三个 JSON 文件都须为 root:root 的独立普通文件，绝对无链接路径及目录链不可被非管理员写入。安装记录必须来自此前可信管理流程；新脚本不生成或认证历史来源，不能将任意手工 JSON 变成可信安装记录。管理员是记录的信任根，能够修改受保护记录的管理员不属于本校验抵御的攻击者。

安装记录字段：`schema_version: 1`、`project: "vpngate-auto-proxy"`、非空 `version`、`entry_path`、`binary_sha256`、`release: {path, source, sha256}`、非空 `instances: [{id, runtime_dir}]`。`release.path` 是明确选定的原构建/发布 JSON 材料，`source` 登记原来源，材料摘要须匹配；材料含相同 `project`、`version` 及 `binaries: {"vpngate-auto-proxy": "程序SHA256"}`。实际公开节点须与记录及材料的完整路径、版本、摘要绑定。

正常停止证明字段：`schema_version: 1`、`installation_sha256`、当前 `/proc/sys/kernel/random/boot_id` 的 `boot_id`，以及与安装清单顺序和数量一致的 `instances`。每项含相同 `id`（规范 UUID）和 `runtime_dir`、原受信管理流程捕获的 `response: {result: "accepted", instance_id}`、整数 `exit_code: 0`、`resources_reaped: true`。这些是可信管理流程留下的证据，不能根据退出码或布尔值自行重建。本脚本还必须核对运行目录已消失、保护父链可核验，并扫描可见 `/proc` 的 exe、fd 和 maps；存活、映射或无法核对的消费者均拒绝，不发送任何信号。

支持退休的公开目录限定为 `/usr/local/bin`、`/usr/bin` 或 `/opt/<应用>/bin`，实际父目录必须恰为该公开目录；不接受更深层的 bin，也不因祖先含 bin 就放行。应用目录名不得为 backup、backups、data、history、versions（不区分大小写）；备份、数据及历史目录拒绝。其他位置保持拒绝。在能看到全部所属进程的原部署进程命名空间执行，不在容器内退休宿主程序；可信记录必须覆盖所有所属实例。独立测试容器只验证该容器内部构造的历史安装和消费者，不代替宿主归属证明。缺少完整可见性或可信旧格式材料时，由管理员另行核实，脚本保持拒绝。

源文件、三个证据和旧入口在审计时持有文件描述符，删除前复核证据、目录、设备号/inode、属主、权限、链接数及内容变更时间；节点变化拒绝。没有记录、旧材料格式不适用或旧停止过程未保存证据时，不自动迁移记录格式。

| 位置 | 约定 |
| --- | --- |
| 实际产品文件 | `/usr/local/bin/vap` |
| 旧产品路径 | 新镜像中既不是文件也不是链接 |
| 默认入口 | 保留 tini 和现有入口脚本，最终执行 vap；环境生成同样调用 vap |
| 容器内管理 | `docker compose exec -T proxy vap status ...`，停止同理 |
| 存活检查 | 调用 vap status，仍不以出口就绪决定容器存活 |
| JSON 与环境模式 | 都保留；地区、时区、凭据及默认回环发布约束不变 |
| 内部安全约束 | 只读根、缓存卷、秘密挂载、能力、专用策略与 no-new-privileges 保持 |

AppArmor profile/对端、编排项目、镜像仓库、许可目录和实例标识保持原名称，不能进行无差别字符串替换。容器默认入口接受原有子命令参数，不要求额外重复输入 vap。

## 部署准备增量（003）

版本化的 `vap-host-init-vX.Y.Z.py` 是独立宿主部署材料，定位与既有安装脚本一致，不是第二产品命令，不安装代理或创建包装器。固定版本引导先校验再执行，保持唯一 vap 产品入口与现有权限边界；新增附件先于同版本及 latest 镜像公开，完整来源与许可继续保留。规则见[宿主准备契约](../../003-deploy-logging/contracts/host-setup.md)。
