# 公开命令与帮助契约

本契约定义当前接口，对应需-001—需-007、需-010。它替代旧功能契约中的公开程序名称约定；旧网络与生命周期契约继续适用。2026-10-16 已完成本地 Docker 两配置模式、无网络帮助及普通契约验证；原生目标矩阵仍按独立范围记录。

## 公开操作

| 命令 | 约定 |
| --- | --- |
| `vap run --config PATH` | 前台运行，既有配置、权限与依赖检查不变 |
| `vap status --runtime-dir PATH` | 人类可读状态，沿用实例时区 |
| `vap status --runtime-dir PATH --json` | 标准输出仅一个既有状态 JSON，不混入帮助或日志 |
| `vap status --runtime-dir PATH --check-ready` | 就绪 0、存活但未就绪 3；不发起额外出口检测 |
| `vap stop --runtime-dir PATH` | 请求并等待所属实例正常回收 |
| `vap help`、`vap --help` | 中文总览，标准输出，退出 0 |
| `vap help run`、`vap run --help` | 启动参数说明，退出 0 |
| `vap help status`、`vap status --help` | 运行目录、机器输出、就绪及状态 3 的说明，退出 0 |
| `vap help stop`、`vap stop --help` | 所属实例停止和运行目录说明，退出 0 |
| `vap --version` | 以 vap 开头，包含实际程序版本和自动节点代理身份，退出 0 |

`PATH` 为待用户填写的路径占位，不修改现有参数拼写或默认路径规则。`--json` 与 `--check-ready` 可组合使用。

## 中文帮助最低内容

总览包括程序用途、用法、run/status/stop/help 列表、帮助/版本选项及至少一组操作示例。所有可执行示例以 vap 开头，不显示旧名入口。程序参数名称保留现有英文拼写，说明正文、标题和内置帮助操作说明为简体中文。

run 的 --config 与 status/stop 的 --runtime-dir 需说明必填、路径用途；status 的 --json 说明机器输出，--check-ready 说明就绪含义及未就绪返回 3。内部 container-config、controller、worker、namespace-setup 和苹果辅助命令不出现在总览，也不接受公开 help 操作查询其详情。

## 错误与无副作用约束

没有子命令、未知子命令、缺少必填参数、非法参数以及未知/隐藏帮助目标均返回 2。错误写标准错误、包含中文分类和 `vap help` 提示，标准输出不混入服务日志；不能默认为启动或执行外部命令。

没有子命令时还显示中文 `用法：vap <操作> [参数]`。错误提示中的操作示例必须能直接执行，例如 `vap help status`，不将斜杠拼接的多个操作当作一个帮助目标。

帮助选项由既有参数解析器识别并遵守 `--` 分隔符；分隔符之后的 `--help`、`-h` 不作为帮助请求。无效操作参数按解析器正常顺序拒绝，不能通过扫描后续帮助字符串绕过校验；公开帮助正文仍为中文，隐藏目标保持拒绝。

帮助和版本在无配置、无管理员权限、无外网时成功；不创建实例目录、网络或缓存，不接入控制通道。显式帮助请求不因缺少运行参数而失败，例如 `vap help run` 不要求 --config。

运行/通信失败、正常结束、未就绪和回收失败继续使用既有状态 1、0、3、4。未启动实例时的 status/stop 保持既有语义，不改状态 JSON 或身份关联。内部命令仍由既有授权链调用，不因隐藏帮助而改变内部功能。

容器生命周期补充：容器内执行 `vap stop` 后，PID 1 正常结束可能使仍在轮询的容器执行进程被终止，容器执行层返回 137。它不属于程序新增的退出语义，也不能单凭该值判定回收成功；受控验收同时核对主服务退出 0、十五秒预算和归属资源回收。日常容器停止使用编排入口。
