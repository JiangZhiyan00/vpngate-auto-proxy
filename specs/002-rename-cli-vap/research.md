# 技术研究与决策：vap 命令

日期：2026-10-15，上海时区。研究包括本地源码只读核查、两个并行研究任务以及官方构建/命令解析文档。未修改实现，未运行特权或网络代理实验。

## 一、单独修改二进制目标

**决策**：保留 Cargo 包 `vpngate-auto-proxy` 及库 `vpngate_auto_proxy`，唯一产品二进制目标改为 `vap`；显式绑定 `src/main.rs`，禁用隐式二进制发现，默认运行目标设为 vap。

**理由**：实际可执行文件名和包名可独立配置；测试的 `CARGO_BIN_EXE_<name>` 随二进制目标变化。官方定义见 [Cargo 目标文档](https://doc.rust-lang.org/cargo/reference/cargo-targets.html#binaries)。本地 Cargo.toml 目前未显式声明二进制，旧名称由包名推导。

**备选**：整体重命名包会连带库导入、锁文件及材料身份；只修改帮助显示名不会产生真实 vap 文件；增加别名违反用户确认。新产物使用干净目录验收，本地旧 target 残留不作为新版本交付。

## 二、复用锁定解析器提供完整中文帮助

**决策**：沿用锁文件 clap 4.6.7，固定 name/bin_name 为 vap，保留参数解析及隐藏子命令。显式提供仅针对 run/status/stop 的中文 help 操作，支持总览、子命令帮助和 --help。参数错误保留状态 2，中文提示指向 vap help；版本保留项目身份及包版本。

**理由**：锁定版本已提供命令显示名、二进制用法名、帮助模板及自动帮助子命令控制接口；无需新增依赖或自行重写参数解析。见 [clap 命令接口](https://docs.rs/clap/4.6.7/clap/struct.Command.html)。本地 src/main.rs 当前仅有顶层模板，参数说明和自动帮助操作仍需完善。帮助/版本解析必须在现有服务初始化及内部辅助派生之前结束。

**备选**：直接接受默认英文帮助不能满足中文说明；无条件自动生成所有子命令的帮助可能暴露隐藏辅助操作；独立手写解析器会增加维护并改变参数边界。只对帮助路由和显示进行定制，不改变授权协议。

## 三、执行路径与项目身份分离

**决策**：替换实际可执行路径和测试二进制目标；保留项目、镜像、策略、许可目录、编排和数据身份。

**理由**：本地研究定位到 Dockerfile 构建复制及健康检查、entrypoint 两处调用、cloud_deploy/validate_docker/validate_soak 的 docker exec、三个发布打包器的程序摘要提取，以及运行库来源采集。漏改任一项会造成构建、健康或发布失败。策略规则中的 signal/ptrace 对端与同名 profile 相关，不能全局替换。

**备选**：对整个仓库执行字符串替换会改写历史证据并破坏归属标记；保留旧程序再增加短包装器违反只提供 vap 的要求。详细文件映射列于 plan.md。

## 四、原生安装及内部派生

**决策**：新公开 basename 为 vap。Linux 安装步骤先检查已存在的同名入口，再用不覆盖的方式安装；拒绝无关文件、链接及无法证明归属的已有目标。苹果 program.rs 的 NAME、安装记录路径、提交及 decode 校验一起改名；保留固定父目录和原子不覆盖提交。苹果通过受保护新程序所在目录的 PATH 配置使用短命令，不额外引入公开链接或包装层。

**理由**：program.rs 的 verify_current 根据 current_exe 核对程序真实路径、管理员归属、模式、摘要和系统加载库。controller、supervisor、tunnel 和 deployment 使用这一身份派生进程；service/netd 也使用当前程序。process.rs 和 spawn.rs 不含名称依赖，不应改变租约与描述符同步语义。现有受保护安装可复用，跨目录链接需要额外平台证明，对本次需求没有必要。

**备选**：使用 PATH 搜索 vap 派生特权子进程存在身份替换风险；覆盖安装或按旧名称批量删除会破坏无关文件；为方便命令创建一个指向旧名程序的兼容包装不符合用户要求。

**安装原子性补充**：官方 [Cargo 安装说明](https://doc.rust-lang.org/cargo/commands/cargo-install.html)明确区分其他包冲突与同包重装，未加 --force 也不能作为任何已有目标均不覆盖的保证。因此生产 Linux 安装采用专用步骤的同目录暂存加排他发布，现有节点一律先报冲突；Cargo 安装仅用于隔离目录的构建/开发验证。目录和源文件归属、普通文件及并发提交必须分别验证，不能只在写入前做一次 exists 检查。

## 五、升级及验证边界

**决策**：只在停止相关实例后、依据既有程序/安装材料证明归属，再由明确升级步骤移除本项目旧公开入口；未知入口拒绝处理。历史摘要目录、用户备份和旧版本报告保持原状。公开镜像重新构建并核验程序、材料和实际短试，保留两个配置模式。

**理由**：命令改名不能绕过已有生命周期与分发门槛。现有 Linux 原生和苹果完整恢复仍有未完成验收；纯命令回归不替代这些目标。正式发布以新提交冻结材料，不修改旧标签或旧报告。

**备选**：自动删除所有同名文件、复用旧镜像摘要或重写历史报告均不能提供可靠归属证据。无新网络行为、无关联失败时不机械重跑三十分钟容量。
