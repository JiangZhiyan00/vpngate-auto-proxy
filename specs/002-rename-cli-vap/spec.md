## 用户场景与测试

### 用户故事一：用短命令管理代理（优先级一）

使用者希望安装或升级后，直接使用 `vap` 启动、查看和停止代理，不再输入原来的长命令名，也不需要自行设置命令别名。

**优先原因**：这是本次需求的核心价值，覆盖日常全部管理操作。

**分阶段验收**：先独立验证唯一 vap 产物、安装冲突拒绝及本地控制契约，称为“核心实现增量”，不据此认定本故事所有场景完成。随后在既有已验证部署环境，用 vap 完成实际启动、状态、就绪与停止；这部分与故事三的真实受控链路合并验收，齐备后才认定本故事完成。

**验收场景**：

1. **给定**已经按项目说明完成新版本安装，**当**执行 `vap run --config /path/config.json`，**则**使用所选配置启动，继续执行原有权限、配置及依赖检查。
2. **给定**运行中的实例，**当**执行 `vap status --runtime-dir /path/runtime --json`，**则**仅输出原状态结构，不因命令改名改变字段或就绪含义。
3. **给定**尚无已验证出口的存活实例，**当**执行 `vap status --runtime-dir /path/runtime --check-ready`，**则**维持原未就绪退出状态；不能把命令可用当作出口就绪。
4. **给定**本实例正在运行，**当**执行 `vap stop --runtime-dir /path/runtime`，**则**按原约束正常停止及回收资源，不影响其他实例。

### 用户故事二：通过帮助了解操作（优先级一）

使用者不需要查阅源码，即可通过帮助操作了解如何启动、查询、检查就绪和停止，以及各操作需要填写的参数。

**优先原因**：用户明确要求提供帮助操作；短命令必须同时具有可发现的用法。

**独立验收**：在无管理员权限、未准备代理配置及无外网的环境运行帮助和版本查询，核对内容和退出状态。

**验收场景**：

1. **给定**程序可执行，**当**执行 `vap help` 或 `vap --help`，**则**显示简体中文总览、以 `vap` 开头的用法，以及启动、状态、停止和帮助操作的说明，成功退出。
2. **给定**需要了解某一操作，**当**执行 `vap help run`、`vap help status` 或 `vap help stop`，**则**显示相应参数及其含义；状态帮助明确说明机器输出、就绪检查和未就绪退出状态。
3. **给定**无配置文件、没有管理员权限且没有外网，**当**查询帮助或执行 `vap --version`，**则**查询成功，不启动代理、不访问外网、不创建实例网络或持久数据。
4. **给定**输入不存在的子命令或无效参数，**当**执行该命令，**则**按原参数错误退出状态失败，并提示使用 `vap help` 查看合法用法；提示中不把旧命令名作为可用入口。

### 用户故事三：部署与说明统一入口（优先级二）

部署者希望新版本原生交付、容器内管理、健康检查和使用文档统一使用 `vap`，避免镜像能启动但管理命令或帮助示例不可执行。

**优先原因**：避免遗漏部署链路；仍遵循容器优先、其他平台按既有支持范围交付的顺序。

**独立验收**：在本次发布实际覆盖的部署环境，逐一核对公开操作、容器存活检查和入口示例；历史记录单独保留。

**验收场景**：

1. **给定**本次交付的容器镜像，**当**启动默认服务、执行容器内 `vap` 状态查询或运行存活检查，**则**调用均有效，保持现有环境配置、认证、隔离和停止行为。
2. **给定**本次新安装或受项目管理的升级，**当**检查公开命令入口，**则**只提供 `vap`，不提供旧名称 `vpngate-auto-proxy` 的兼容入口。
3. **给定**本次发布的使用说明和帮助示例，**当**使用者按说明操作，**则**全部当前命令示例使用 `vap`，版本查询仍能辨识项目和版本。

### 边界情况

- 未启动实例时的状态和停止操作，沿用既有错误或幂等语义，不为改名调整行为。
- 帮助与版本查询不要求管理员权限；启动和管理所需权限保持原约束，不为短命令降低权限要求。
- 未知子命令、缺少必要参数及非法参数必须失败，不能默认为启动代理。
- 内部辅助操作不作为公开命令展示；改名不能破坏代理正常启动、故障阻断或回收。
- 已存在其他软件提供的 `vap` 时，安装或升级须明确报告冲突，不静默覆盖无关程序。
- 不兼容旧名称只适用于本次新交付及其管理的升级；不回写历史版本或验收证据，也不删除用户自行保存的旧程序及无关命令。
- 原生环境中未包含程序所在目录时，应通过安装或部署说明解决命令可发现性，不依赖用户自行设置短命令别名。

## 需求

### 功能需求

以下编号仅属于本功能，既有代理能力和支持矩阵以[原功能规格](../001-vpngate-auto-proxy/spec.md)为基础。

- **需-001**：新版本公开命令名称必须为 `vap`；新安装及项目管理的升级必须可按说明直接使用该名称，不要求用户手工创建别名。
- **需-002**：必须保留现有公开子命令及参数的含义，包括 run、status、stop、帮助、版本、机器状态和就绪检查；只改变入口名称，不简化或删除现有必要参数。
- **需-003**：新交付不得提供旧命令名 `vpngate-auto-proxy` 的兼容入口；当前使用文档不得将旧名称作为可执行操作指导。历史记录和明确标注的迁移说明可以保留旧名称。
- **需-004**：必须提供 `vap help` 和 `vap --help` 总览，成功退出；帮助正文和参数说明采用简体中文，用法中的公开程序名统一为 `vap`。
- **需-005**：必须提供 `vap help run`、`vap help status`、`vap help stop` 的具体帮助，说明必填参数、可选参数及其用途；状态帮助需解释就绪检查与机器输出。
- **需-006**：帮助和版本查询必须在无管理员权限、无运行配置及无外网时成功，不创建代理实例、网络资源或持久数据；内部辅助操作不列入用户帮助。
- **需-007**：参数错误继续采用退出状态 2，并指向 `vap help`；正常完成、运行失败、未就绪和回收失败继续采用既有退出状态 0、1、3、4。
- **需-008**：本次交付的容器默认启动、容器内管理及存活检查必须使用可用的新入口，环境配置、凭据路径、持久数据、状态协议和实例归属语义保持兼容。
- **需-009**：本次发布的原生使用说明、容器操作、帮助和发行说明必须统一使用 `vap`，并说明这是不保留旧名称兼容入口的变更；不得据本次改名宣称此前未验证的平台已支持。
- **需-010**：版本查询必须继续清晰标识项目及实际版本；发生无关同名 `vap` 冲突时必须明确报告，不能静默覆盖或接管。

本功能不新增业务数据实体，不改变节点、配置、状态及实例身份的数据含义。

- 用户明确要求移除旧命令，不设置别名或兼容过渡期；这一确认替代此前提出的保留旧命令建议。
- “vap xxx”指统一公开程序入口，不要求把 run、status、stop 改成其他子命令，也不要求改动镜像仓库名、项目名称、配置字段、数据目录或发布标签规则。
