## 摘要

将唯一用户可执行文件改名为 `vap`，不保留旧命令别名；沿用现有 run、status、stop 参数、退出码和内部派生链。使用现有命令解析依赖提供中文 `vap help`、子命令帮助和错误提示。同步容器、验收及分发工具的实际程序路径，保持包名、镜像名、策略名和持久目录身份。设计及任务已完成，并于 2026-10-16 实施；实际产物及边界见[实施验证](../../docs/validation/vap-cli.md)。

## 阶段零：研究结论

1. 保留 package 名，显式声明唯一 `[[bin]]` 为 vap、源码仍为 src/main.rs；禁用隐式二进制发现并设置默认运行目标，避免重新产生旧名目标。库导入和锁文件包身份保持不变。
2. 公开入口和显示名称均为 vap；明确 help 操作只接受公开子命令，避免自动帮助泄露隐藏内部操作。解析错误统一中文分类并指向 vap help；帮助和版本在服务初始化前结束。
3. 所有执行、构建和二进制摘要读取路径同步改名；策略、镜像、许可目录和归属标识不跟随改名。参考字符串审计只作定位，不作全局替换。
4. 原生安装采用冲突检测和无覆盖发布。苹果继续使用受保护的版本加摘要目录，文件名改 vap；通过该目录的 PATH 设置使用短命令，不增加指向旧程序的兼容包装。内部派生不依赖 PATH。
5. 新安装不提供旧入口；升级仅处理可证明项目归属的旧公开入口，无法证明时报告并停止，不删除用户保存的程序或历史摘要目录。安装不自动启动或停止实例。

旧入口处理采用独立明确的退休操作，与安装流程分开；必须遵守部署契约的材料关联、root 保护、设备号/inode 复核和已停止实例证明。仅有正确文件名或手填摘要不能授权删除。当前没有可信旧记录的手工部署按未知归属处理，不自动生成“迁移成功”结论。

研究依据、备选和文件影响见[研究记录](research.md)。

## 阶段一：设计与验证顺序

### 命令与帮助

保留公开参数与隐藏内部命令；固定显示/用法名称，帮助说明补齐配置路径、运行目录、机器状态和就绪检测。普通无参数调用视为缺少必要操作，显示中文用法并返回 2，不启动实例。`vap help` 与 `vap --help` 返回 0；不存在或隐藏的帮助目标返回 2。版本格式保留项目标识和实际包版本，不把 Docker 标签当作程序版本。

### 构建、安装与交付

先在干净产物目录确认只生成 vap，测试改用 CARGO_BIN_EXE_vap。受保护安装记录的新 basename 与程序路径校验一起修改，保留原有 NOREPLACE、权限、摘要和系统库核验。Linux 公开安装步骤以 scripts/install-vap.py 封装：预检同名冲突和目标目录，以同目录暂存加排他发布保证不覆盖，失败只清理本次暂存；不加入通用全局清理器。Cargo 安装只用于独立目录构建/开发验证，不把其同包更新语义当作严格不覆盖保证。苹果新安装返回受保护路径，先核验该路径，再将其所在目录加入 PATH；旧受保护摘要目录保持历史材料属性，不作为新版本公开入口。

Docker 构建仅复制 `/usr/local/bin/vap`；入口脚本、健康检查、状态/停止、环境配置转换与发布摘要读取统一用该路径。保持 `/usr/share/licenses/vpngate-auto-proxy/`、AppArmor 名称和编排项目标识。新镜像中旧路径不存在；旧公开镜像不原地修改。

### 测试与文档收口

US1 的 T009 只完成核心实现增量，包括干净产物、安装及本地控制契约；US1 的实际启动/状态/就绪/停止四个场景与 US3 的 T021 合并执行，四项成功标准最终在 T024/T025 追溯。任何早期阶段不得因此声明 US1 全部验收完成或可单独公开发布。生产安装的真实 root 行为可在无网络独立 Linux 测试容器验证；普通用户注入元数据测试不计为该目标通过。

顺序为：公开帮助/参数错误契约 → 唯一构建目标 → 源码及工具调用联动 → 无覆盖安装和受保护记录回归 → 本地无网络容器帮助及旧入口缺失 → JSON/环境模式受控短试 → 新程序摘要和来源核验 → 当前文档一致性及独立验证记录。共享文件依赖串行处理，不能只改二进制后用残留旧文件通过测试。

覆盖需-001—需-010 与成-001—成-004 的具体矩阵见[快速验收](quickstart.md)。更新 `001` 的当前命令契约时标明被新规格替代的范围，保留原验收报告和未完成任务。不得重写历史构建摘要或以本次命令回归勾选原生网络、苹果恢复或真实远端发布任务。

### 停止条件

帮助触发网络或特权初始化、隐藏操作泄露、旧目标仍被新交付、安装覆盖未知程序、摘要工具读取旧路径、认证/故障阻断/回收回归失败时，不进入发布。目标环境不可执行的用例明确记为未执行，不静默跳过后宣称全矩阵通过。

## 实施结果（2026-10-16）

唯一 vap 目标、中文帮助、Linux 无覆盖安装及独立退休、苹果受保护记录名称和全部实际调用路径已实施。干净构建、普通契约、无网络非管理员帮助、两配置模式真实容器短试及完整来源/包核验通过。新增共享 `scripts/image_program.py` 统一三个分发器的只读程序快照，云端离线包包含其运行依赖；公开来源包含新命令及退休契约。

Linux root 安装正反用例仅在无网络独立容器执行，苹果仅普通组件。新镜像强制 AppArmor、目标原生矩阵及真实远端发布未执行；本地停止验证保留容器执行层终止码及主进程正常回收证据，不能将其当作新的 CLI 退出码。

2026-10-16 收敛修复：公开目录退休判定收紧为标准目录或 `/opt/<应用>/bin` 的固定层级，拒绝备份、数据与历史目录；无参数返回 2 时显示中文用法，错误示例可直接执行。新增任务 T026/T027 的真实回归和新候选分发核验完成，见收敛验证记录；不改变原平台、网络或发布授权边界。

2026-10-16 审查修复收口：T028 由现有 clap 识别帮助选项与分隔符，只定制公开中文显示，不再扫描所有原始参数；T029 将有效的 SUDO_UID=0 视为 root 身份且不扩大来源 UID。两项边界测试、普通回归及新镜像两模式/完整分发核验通过，证据见审查修复记录；平台与发布边界保持。
