**功能目录**：`specs/003-deploy-logging`
**当前分支**：`main`；本次未创建或切换分支。
**创建日期**：2026-10-16，上海时区。
**状态**：已完成 42／58 项。宿主准备工具、Linux／Docker 日志及启动摘要已实现并通过本地回归和十分钟容器验收；真实宿主 enforce／重启、强制 AppArmor 最终镜像门禁、正式材料冻结及苹果专用实现／验收仍未完成。详见[验证汇总](../../docs/validation/deploy-logging-summary.md)。

## 用户场景与测试

### 用户故事一：一次完成宿主首次准备（优先级一）

部署者希望执行一次清楚、简短的宿主初始化操作，完成所选版本专用安全策略的准备及检查；随后在 Portainer 或 Docker Compose 中直接启动、重启和更新代理，无须手工重复下载、安装和加载策略。

**优先原因**：现有容器在策略未加载时无法启动，界面只显示通用部署错误，多条宿主操作影响首次部署体验。

**独立验收**：在支持范围内的干净宿主，以及已有代理和其他服务运行的宿主，验证首次准备、重复调用、失败及重启后的结果，无须公共代理节点可用。

**验收场景**：

1. **给定**具备必要依赖但尚未安装项目策略的宿主，**当**管理员通过唯一文档入口执行首次准备，**则**一次调用完成对应版本策略的准备、安装、加载和结果检查，并说明现在可以启动代理。
2. **给定**同版本准备已经完成且内容一致，**当**重复调用，**则**报告已就绪，不重复修改有效内容，不重启容器引擎、其他容器或活动代理。
3. **给定**准备成功后宿主按支持范围的方式正常重启，**当**检查准备状态并启动代理，**则**所需策略仍可用，无须手工再次加载。
4. **给定**权限不足、依赖缺失、安全模块不可用或来源材料校验失败，**当**执行准备，**则**报告失败项及下一步操作，不声称完成，不关闭安全保护，不修改其他应用策略。
5. **给定**现有项目策略包含未知本地修改，**当**初始化或更新，**则**说明冲突并拒绝静默覆盖；合法版本更新具有明确操作和可核对结果。

### 用户故事二：按需要控制日志量（优先级一）

运行者希望日常只看到启动、出口变化和重要异常，在排障时开启详细日志，并可调整周期摘要频率，避免每秒刷屏。

**优先原因**：目前运行摘要固定每秒输出，增加阅读和存储负担；控制日志量应独立于实际健康检查频率。

**独立验收**：对同一组受控启动、候选检测、出口故障和恢复场景配置不同等级、摘要间隔，比较可见事件，并核对代理状态和调度未改变。

**验收场景**：

1. **给定**未配置日志选项的现有配置，**当**启动新版代理，**则**默认使用 `info`，显示重要生命周期事件，常规候选检测、成功健康检查和周期摘要不持续刷屏。
2. **给定**选择 `error`、`warn`、`info` 或 `debug`，**当**产生不同严重程度的事件，**则**只显示所选等级及更严重事件；非法等级在创建运行网络资源前拒绝。
3. **给定**使用 `debug` 且省略摘要间隔，**当**持续运行，**则**周期摘要默认每 60 秒至多一次；指定有效间隔后按所选值输出。
4. **给定**使用 `warn` 或 `error`，**当**正常启动运行，**则**信息等级的启动摘要不输出，警告和错误按等级保留，独立状态查询仍可用。
5. **给定**原生文件和容器环境配置指定相同日志选项，**当**启动，**则**过滤结果相同；修改选项后在实例下次启动生效。
6. **给定**内部工作进程或受项目管理的外部隧道程序产生输出，**当**降低详细程度，**则**普通详细输出不绕过日志策略持续刷屏，关键失败仍有可定位诊断。

### 用户故事三：启动后立即了解有效配置（优先级二）

使用者希望从日志确认本次实际监听地址、端口和主要设置，并区分服务已经启动与代理出口是否可用。

**优先原因**：减少部署后猜测端口、地区和时区的成本，避免误把容器启动当作出口就绪。

**独立验收**：使用不同于默认值的配置，在有出口、无出口和端口占用三种受控条件下启动，核对摘要时机、有效值及敏感信息保护。

**验收场景**：

1. **给定**采用默认 `info` 且服务已实际完成监听，**当**启动成功，**则**每个实例只输出一次摘要，包含监听地址与端口、代理协议、地区筛选、时区、连接上限、日志等级、摘要间隔、数据和运行目录，以及认证是否启用。
2. **给定**容器内部监听 `0.0.0.0:1080`，宿主映射端口不同或未发布，**当**输出摘要，**则**明确标识为容器内部监听信息，不猜测宿主端口，不宣称公网可达。
3. **给定**监听完成但尚无已验证出口，**当**输出摘要，**则**说明服务已启动、出口尚未就绪；出口验证成功后另行报告就绪变化。
4. **给定**端口占用、配置错误或预检失败，**当**启动中止，**则**有具体失败诊断，没有启动成功摘要。
5. **给定**凭据或配置包含密码、令牌、私钥或带认证信息的地址，**当**输出任意等级日志、启动摘要及错误，**则**不泄露这些值或敏感配置正文。

### 边界情况

- 权限不足时在修改宿主状态前拒绝，不尝试隐式提权。
- 不支持的宿主、安全模块或依赖应明确报告；不能自动关闭 AppArmor、启用不受限容器或扩大生产能力集作为回退。
- 材料下载、校验、安装或加载失败必须报告阶段，不能把部分完成当作已就绪；已有有效策略不得被失败操作破坏，必要时提供恢复步骤。
- 并发初始化不得相互覆盖或报告虚假成功；冲突须拒绝或等待，并能核对最终状态。
- 已有多服务编排中，首次准备不重新部署、停止或重启整个 Stack；普通代理操作不改变其他服务。
- 长期等待节点时保留状态变化和失败诊断，不持续重复相同等待信息；日志变化不改变退避规则。
- 摘要间隔只接受 1—86400 秒整数；零、负数、小数、越界值和未知等级均拒绝，不得造成忙循环或意外默认行为。
- 隐藏周期摘要不影响状态查询，多进程采用同一实例的有效日志配置。
- 出口切换和恢复不重复打印启动配置摘要，实例重新启动可以再次打印一次。
- 日志不能插入控制操作的机器输出；参数、配置及致命错误在全部允许等级下均保留。
- 诊断队列拥塞时生产者不等待日志交付：启动摘要保留独立槽位，普通事件按严重程度淘汰或合并并计数；关键退出阶段及原因另由可信失败结果保留，不能只依赖日志队列。日志接收和输出目标故障不能阻止业务故障阻断或延长原停止预算。
- Linux／Docker 与苹果验收独立记录；苹果验收未完成不阻塞仅声明 Linux／Docker 范围的交付，也不得被该交付冒称已经通过。

## 需求

### 功能需求

本节编号仅属于本功能。既有代理隔离、故障阻断、认证、能力边界、`vap` 命令和发布约束继续适用。

- **需-001**：为 Linux 容器部署提供一个文档化的宿主首次初始化入口，一次调用完成项目专用策略的准备、安装、加载和检查；新增公开产品命令继续使用 `vap`。
- **需-002**：准备操作检查管理员权限、支持范围及必要条件，提供逐项结果和具体失败原因；全部通过后才能报告可启动，准备完成不代表出口就绪。
- **需-003**：准备操作只修改明确归属本项目的策略材料，不自动安装或升级容器引擎，不操作其他服务，不关闭防护；生产容器既有必要能力边界保持不变。
- **需-004**：策略材料对应明确项目版本，使用前校验来源和完整性；同版本准备可重复执行，拒绝静默覆盖未知本地修改；失败时保留已有有效状态或说明恢复步骤。
- **需-005**：策略安装纳入支持的宿主启动管理范围，正常重启后无须用户手工加载；同版本普通容器更新不要求再次初始化，版本不匹配时明确提示所需更新而不自动操作活动服务。
- **需-006**：提供首次部署、重复检查、策略更新和 Portainer 已有 Stack 的简体中文操作说明，明确宿主准备和容器启动的不同权限范围；不要求下载完整源码或自行拼接多条策略准备命令。
- **需-007**：日志等级只支持小写 `error`、`warn`、`info`、`debug`，默认 `info`；严重程度由高到低依次为错误、警告、信息、调试，输出所选等级及更严重事件。未知值拒绝，不提供吞掉错误的静默等级。
- **需-008**：文件配置与容器环境配置都支持日志选项；公开名称分别为 `log_level`、`log_summary_interval_seconds` 和 `VAP_LOG_LEVEL`、`VAP_LOG_SUMMARY_INTERVAL_SECONDS`。旧配置省略时采用默认值，容器空值视为未设置，修改在下次实例启动生效。
- **需-009**：启动、正常停止、出口切换及恢复等生命周期事件归入信息；来源获取失败、活动出口失效及可恢复异常归入警告；导致操作或服务失败的错误归入错误；常规候选检测详情、成功健康检查及周期摘要归入调试。普通不可用候选不逐个作为警告刷屏。
- **需-010**：周期摘要默认间隔 60 秒，允许 1—86400 秒整数；只在等级允许时显示，首次调试摘要可立即输出，此后相邻周期摘要不得小于所选间隔。非法选项在创建运行网络资源前拒绝。
- **需-011**：等级过滤和摘要频率覆盖监督、控制、业务工作进程及受管理外部程序输出；普通详细输出不得绕过过滤。队列满时不得阻塞控制和清理，启动摘要独立保留，普通事件按等级合并或淘汰并记录交付损失计数；关键退出阶段及原因通过独立于日志排队的可信失败结果保留，不直接复制未经审查的敏感原始输出。
- **需-012**：日志配置只影响可见输出，不改变候选调度、健康检查、出口选择、认证、路由隔离、故障阻断、状态查询和资源清理。
- **需-013**：成功启动后生成一次信息等级的有效配置摘要，至少包含监听地址、端口、代理协议、地区筛选或全部地区、时区、连接上限、日志等级、摘要间隔、数据目录、运行目录及认证启用状态；展示解析后的实际生效值。
- **需-014**：摘要只在配置校验、必要预检及真实监听完成后输出，启动失败不得产生成功摘要；明确区分服务已启动、出口未就绪与出口已就绪。
- **需-015**：容器摘要明确地址属于容器内部，未经可信依据不得报告宿主映射端口、公网地址或外部可达性，不为获取这些信息新增宿主管理访问权限。
- **需-016**：启动摘要遵循信息等级过滤，`warn` 或 `error` 下不输出；状态和就绪查询保留原有独立能力。每个实例最多一次启动摘要，出口变化另行报告。
- **需-017**：所有等级继续保护敏感信息，配置摘要仅输出明确允许的安全字段；不打印密码、令牌、私钥、凭据文件内容或带敏感信息的完整地址，认证仅显示是否启用。
- **需-018**：日志保留既有时间、类型、节点、工作进程、状态及原因等可追溯信息，并明确严重程度；不向机器状态输出插入日志正文，现有解析和部署验收按约定继续可用。
- **需-019**：帮助、容器示例及部署说明同步配置默认值、范围和生效时机，区分日志轮转与输出等级；示例不把容器存活或启动摘要等同于出口可用。

### 关键实体

- **宿主准备结果**：项目版本、支持范围、策略安装和加载状态、逐项检查结果及失败阶段，描述部署前提而非业务就绪。
- **日志策略**：本次实例生效的等级和周期摘要间隔，在各参与进程间保持一致。
- **运行事件**：具备严重程度、时间、类型和必要上下文的记录；过滤只改变可见性。
- **启动配置摘要**：成功启动的安全有效配置视图，关联本次实例和当时就绪状态，不承载敏感正文。

## 成功标准

### 可衡量结果

- **成-001**：受支持的干净宿主只需一次明确的准备调用；之后连续三次容器启动或更新及一次正常宿主重启均无须手工再次加载策略，其他既有服务不被准备操作重启或修改。
- **成-002**：同版本重复准备三次均报告正确且一致的结果；权限不足、材料校验失败、策略加载失败和本地修改冲突四类失败均无虚假成功，并明确定位失败项。
- **成-003**：默认设置下正常运行十分钟，在没有状态变化或异常的受控环境中，周期摘要、普通候选检测详情和成功健康检查日志为零，重要生命周期信息仍可查询。
- **成-004**：四种等级对同一受控事件序列的过滤全部符合规则；调试摘要在 1、60 和 300 秒设置下不超出配置频率，非法选项全部在运行资源创建前拒绝。
- **成-005**：在日志接收端和输出目标可用时，每次成功启动在实际监听完成后五秒内产生一次信息等级摘要，必需字段全部与有效配置一致；失败启动零条成功摘要，出口变化不增加启动摘要数量。所选等级屏蔽信息时遵循同一过滤约定；输出故障按诊断交付规则处理，不以此改变服务状态或延长停止预算。
- **成-006**：敏感标记检查覆盖四种等级、启动失败和配置错误场景，密码、令牌、私钥和敏感配置正文泄露数量为零；状态查询仍独立辨识出口是否就绪。

## 假设与依赖

- 用户接受宿主首次准备一次，后续通过 Portainer 或 Docker Compose 日常操作；不要求普通生产容器自动取得宿主安全策略管理权限。
- 首要范围是既有 Linux x86_64、有根容器引擎及 AppArmor 的环境，优先覆盖已有 Debian／Ubuntu 验收环境；详细支持矩阵在设计阶段明确，不宣称支持未验证宿主。日志与摘要覆盖现有支持路径，不新增苹果完整后端验收承诺。
- 宿主已有必要系统工具和隧道设备，初始化负责检查及项目策略准备，不扩展为通用服务器安装器。首次获取材料需网络或已校验材料，后续普通容器启动不依赖策略再次下载。
- 采用已讨论的默认信息等级；周期摘要默认 60 秒且属调试信息。未要求热更新，选项修改在实例重新启动或重新创建后生效。
- 启动成功打印配置指默认信息等级下的服务监听成功，不等同于公共出口可用；较严格等级按规则过滤。容器不能仅从内部确定宿主端口，摘要明确内部监听范围。
- 日志磁盘轮转继续由部署平台管理，可在说明中给出示例，但不新增日志收集服务、管理界面或宿主管理接口。
- 本次不修改代理协议、地区选择行为、算法兼容默认值、时区默认值、镜像架构、发布触发规则及验收门禁；允许增加本功能必需的版本化宿主安装器、清单、引导说明及对应校验摘要附件，保持先验收、再公开完整来源、最后推送同一镜像版本和 latest 标签的顺序。不自动提交、推送、移动标签或发布镜像。
