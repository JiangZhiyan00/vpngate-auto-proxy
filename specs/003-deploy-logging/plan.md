## 概要

保持 Docker 运行架构、必要能力、AppArmor 防护和唯一 `vap` 产品入口。通过小型、版本化、先校验后执行的部署安装器完成宿主项目策略准备，后续在 Portainer 或 Compose 中操作代理即可。安装器不安装宿主代理、不要求下载完整源码、不重启其他服务。

运行端新增显式日志策略，保留既有逐行 JSON，默认 info，周期摘要为 debug、默认 60 秒。真实监听成功后产生一次白名单摘要；内部监听、宿主端口与出口就绪含义分开。所有进程统一策略，保留苹果 stderr 租约，不以日志管道替换资源持有机制。

## 阶段零：研究结果

研究已关闭，见 [research.md](research.md)。重点已确定：

1. 使用现有安装工具定位的版本化宿主安装器，先校验后执行；不分发新原生代理或使用特权初始化容器。
2. 固定项目路径、root 保护、独占锁、事务意图、未知内容拒绝、明确接管／更新与完整回收门槛。
3. 真正加载 enforce 与磁盘持久性分别检查；正常重启必须有独立真实证据。
4. 轻量 JSON 日志模块、显式策略传递；摘要定时与网络调度分离。
5. 苹果额外诊断通道独立于控制和资源租约，有限帧及队列；保留关键退出诊断。
6. 真实 listener 持有后输出白名单摘要，不能使用临时端口预检或早期内部 Ready 代替。

## 阶段一：设计与接口

### 宿主准备与发布材料

- `scripts/host-init.py` 是可测试的实现源；打包器生成 `vap-host-init-vX.Y.Z.py`，内嵌唯一生产策略、策略摘要、来源版本及支持矩阵，执行时不从网络读取代码或策略。
- 同版本附件增加 `host-setup.json`、`host-setup-command.txt`，既有 `SHA256SUMS` 追加安装器及清单摘要，保留完整源码归档摘要。引导命令固定官方 HTTPS URL 和安装器预期 SHA，使用 root 私有临时目录，校验成功才运行，成功／失败均清理本次临时材料。
- 默认初始化、只读 `--check`、显式 `--adopt` 和绑定旧版本的 `--update-from vA.B.C` 分别定义；帮助无需特权且无副作用。准备不会启动容器或操作整个 Stack。
- 固定生产策略名不变。已管理、磁盘摘要和 enforce 一致时不 reload；需要替换时拒绝活跃使用者。原子磁盘提交与内核加载不是同一个事务，使用受保护事务意图和可恢复旧材料，任意不确定状态失败关闭。
- 原有 build_inputs 冻结范围扩展至安装器、打包器和策略；最终镜像的策略摘要标签与宿主材料清单、内嵌策略一致。允许增加本功能必要附件及摘要，保持原发布触发规则、验收门禁、先公开完整来源再推送版本及 latest 的顺序；不覆盖既有公开附件或标签。
- 支持的系统启动链检查是准备门槛；安装器不自行 enable／restart AppArmor 或 Docker，检查不足则解释管理员需补齐的宿主条件。

详细契约：[contracts/host-setup.md](contracts/host-setup.md)。

### 日志策略与跨进程输出

- AppConfig 新增 `LogLevel` 和 `log_summary_interval_seconds`，默认 info／60；严格枚举及整数范围，空环境变量使用默认。容器覆盖文件显式转发两个变量，不能只修改转换器而遗漏 Compose。
- 新日志模块以显式实例策略、类型化事件等级和独立摘要白名单构造逐行 JSON。过滤在序列化前；不整体序列化配置，不输出外部任意错误链。
- Linux Bootstrap 已携带配置，监督／控制双方直接复用；受管理外部程序原始输出不公开透传，继续由安全结果说明阶段，必要的排空和读者任务纳入回收。
- 苹果控制进程通过单独诊断通道交付白名单事件；父方验证、补充可信实例归属并按策略输出。每帧上限 4096 字节，总 64 帧中 1 帧保留给首次监听事实、63 帧用于普通事件；完整摘要由父方可信配置重建。生产者非阻塞，满队列按等级淘汰／合并并以四个固定计数器记录损失；关键退出阶段和原因独立保存在可信失败结果中，只有回收布尔量的收据须补充安全原因结果，不用日志成功作为退休确认。
- 不改变 stderr 租约继承，不让日志读者持有业务控制端或隧道句柄。关闭顺序为停止日志生产、关闭本次写端、排空至多 1 秒并回收读者；该秒数包含在原十五秒总停止预算内，剩余预算不足则提前结束。最终输出不可写不改变业务状态，恢复后按等级计数汇总交付损失，拥塞和最终写入不能无限阻塞退出。
- 调试摘要使用独立单调截止时间，第一次可立即输出，后续 `now + interval`，不追补。原健康周期、结构检查和重试退避不变。

详细契约：[contracts/logging.md](contracts/logging.md)。

### 启动摘要与可观测性

- 网关提供一次真实绑定结果和已绑定监听对象；服务循环接管同一对象，不二次 bind，成功摘要放在绑定之后、业务循环及出口提升之前。
- 对外一条 JSON 事件 `startup_summary`，`level=info`，事件外层保持既有字段；`config` 为安全白名单，`ready=false` 表示尚未通过出口验证。
- 容器内部地址与原生进程地址通过可信启动上下文区别；不根据非可信环境参数猜测宿主映射，不引入 Docker socket 挂载。
- 正常服务生命周期、出口提升／撤销与错误继续独立；机器状态查询不增添日志正文或变更退出状态。

详细契约：[contracts/startup-summary.md](contracts/startup-summary.md)，实体定义：[data-model.md](data-model.md)。

### 必须修订的现有验收

- 依赖 candidate_started、round_started、cache_loaded 等事件的旧测试显式使用 debug，另加默认日志安静场景，不能直接删除断言。
- `validate_docker.py` 的候选否定和缓存断言采用状态、持久材料及调试正对照，不能由默认等级下的缺失日志得出未启动候选结论。
- 宿主安装器测试不在普通测试阶段修改实际 `/etc` 或加载内核策略；真实验证工具要求明确目标和授权，不自动重启用户服务器。
- 本机模拟 amd64 或无 AppArmor 引擎只提供部分证据。两种目标发行版的 enforce／重启矩阵、苹果适用回归和公开新附件必须分别标记未验证／通过，不能沿用旧版本证据冒充。

## 设计后章程复核与复杂度

上述设计符合五项章程，无未解决的研究事项，无需豁免。新增复杂度限于项目策略的文件／内核事务和苹果独立诊断通道，均由明确权限及资源约束要求产生；不用关闭安全策略、覆盖未知文件、借用租约 stderr 或扩展宿主代理分发来省略这些边界。

本计划定义设计与验证边界；任务阶段已按三个独立故事生成依赖有序清单，并单列目标环境验收。本次文档修订不运行管理员初始化、不更改用户 Portainer、不执行宿主重启、不提交或发布。
