# 日志配置与输出契约

对应需-007—需-012、需-017—需-019。保持原 JSON 行和标准错误日志方向；公开状态查询的 JSON、含义和退出码不变。

## 配置接口

| 文件字段 | 容器环境变量 | 默认 | 合法范围 |
| --- | --- | --- | --- |
| log_level | VAP_LOG_LEVEL | info | 精确小写 error、warn、info、debug |
| log_summary_interval_seconds | VAP_LOG_SUMMARY_INTERVAL_SECONDS | 60 | 1—86400 秒整数 |

环境变量空字符串视为省略，非空值不自动改大小写或清除空白；`INFO`、`off`、未知值拒绝。环境数字仅无符号十进制整数；文件数字必须为整数，null、浮点数、布尔值、越界值拒绝。旧配置无需新增字段即可启动；日志默认变安静是预期用户行为变更。

原生配置只读取显式文件，不增加宿主环境覆盖；容器专用转换器才消费 VAP_ 变量。Compose 注册表覆盖文件必须显式传入两个变量，Portainer 直接镜像示例同样有效。修改后重新启动或重新创建实例生效，不提供热更新或 RUST_LOG 隐式覆盖。

非法配置沿原参数／配置错误退出语义，指出字段名与安全原因，不能回显未知原始值、完整 JSON、地址或错误链。

## 等级过滤

| 选择等级 | 可见事件 |
| --- | --- |
| error | error |
| warn | error、warn |
| info | error、warn、info |
| debug | 全部四级 |

所有等级保留配置、参数和致命错误。命令帮助、版本、状态及其本来输出不是运行事件，不被日志等级隐藏，也不能混入其他日志正文。

## 事件分类与变化规则

| 等级 | 事件及分类 |
| --- | --- |
| error | 导致启动、控制操作、运行或退出清理失败的错误；内部协议／归属不符合要求的致命错误 |
| warn | source_failed、active_check_failed、活动出口撤销／阻断、cache_write_failed、diagnostics_write_failed；可恢复异常 |
| info | startup_summary、正常停止、active_promoted、出口恢复；来源有效状态、等待状态的实际变化 |
| debug | source_fetch、重复且无变化的 source_updated、cache_loaded、cache_ignored、diagnostics_ignored、pending_started、candidate_started、tunnel_connected、candidate_result、round_started、round_finished、active_check_succeeded、runtime_summary |

实现时枚举并审计全部既有事件，采用类型化映射；不得给未知字符串默认为高等级或静默漏掉新增事件。首次来源有效变化可用信息事件表达，无变化刷新只作调试；等待状态只在变化时输出，不因主循环反复报告。普通候选失败保留安全检查结果，不逐个作为警告；活动出口失败属于警告，真正导致实例终止才属于错误。

既有 Event 字段继续保留，新增小写 `level`。已有日志读者需容忍新增字段；本次测试验证当前读者。配置时区继续控制事件偏移，状态机器时间和预算不变。

## 周期摘要

runtime_summary 仅为 debug。首次允许立即输出；之后相邻两条不得早于配置间隔。采用单调时间，系统时区修改、墙上时钟跳变和调度延迟不导致补发或忙循环。若调度晚到，下一次截止时间按当前时间加间隔，不回补错过的摘要。

过滤发生在构造／序列化前；不能因过滤而跳过刷新、探测、持久化、状态更新、退避、退出或资源清理。摘要截止时间与健康检查、候选轮次及结构检查分别保存。

## 多进程与外部程序

- Linux 启动配置显式携带同一 LogPolicy；env_clear 后不依赖外部环境自动继承。监督与控制的输出均经过统一安全事件接口。
- 外部隧道程序的原始日志不直接输出到公开日志；通过现有管理结果及安全错误分类保留故障阶段。若需要采集详细诊断，持续排空、限制保留字节，并纳入子进程关闭和回收；不能有限读取后放任管道阻塞。
- 苹果消费者的 stderr 描述符用于资源租约，保留原继承与关闭机制，不替换为普通日志目标，不把格式化诊断文字写入租约文件。
- 苹果控制／协调事件通过独立版本 1 诊断通道传给持有实例策略的父方。每帧最多 4096 字节，总缓冲最多 64 帧；其中 1 帧专供本实例首次监听摘要，63 帧用于其他事件。父方按直属消费者、授权上下文、事件白名单及实例核对，不接受任意原始文本作为公开日志。
- 诊断通道无控制权限、不延长管理控制端寿命、不持有额外 utun 句柄；生产者使用非阻塞提交，不同步等待接收端或最终日志目标。满队列处理、关键错误保留和退出时限按下节执行。
- 未知帧、超限帧或归属错误须安全拒绝并有限报告，不导致日志无限递归。日志通道故障不把未验证出口标为 ready，也不改变原故障阻断。

## 队列满、输出故障与停止时限

| 类型 | 满队列时的确定行为 |
| --- | --- |
| startup_summary | 使用独立 1 帧槽位，普通事件不得占用、淘汰或覆盖；重复提交同实例摘要拒绝。父方优先处理，仅传实际监听事实并用已有可信配置重建完整摘要，不把完整配置装入 4096 字节诊断帧 |
| debug | 普通 63 帧已满时丢弃新调试事件，增加固定的 debug 丢弃计数，不等待、不忙重试 |
| 普通 info | 优先淘汰最旧 debug；否则替换最旧同类 info，仍无位置则舍弃新 info 并计数；不能淘汰 warn、error 或启动摘要 |
| warn | 优先淘汰最旧 debug，其次最旧普通 info；若全部为 warn／error，可合并最旧 warn 并保留本次最新安全原因及计数；全部为 error 时只计 warn 交付损失，不阻塞或覆盖 error |
| error | 优先淘汰最旧低等级事件；全部为 error 时合并最旧错误并保留本次最新安全原因及计数。导致退出的具体阶段／原因必须另外保存在可信失败结果中，不得只存在于可能被合并的排队事件 |

丢弃／合并统计只用四个固定等级的饱和计数器，不以节点或任意原因创建无限键；在输出恢复可用后至多每 60 秒发一次 diagnostics_overflow 汇总，等级为发生损失的最高等级，仍受选择等级过滤。计数含已排队但随后被淘汰的事件，不能静默把排队成功当作交付成功。

父方从既有可信控制失败结果或退出收据获得关键退出原因；若原收据只表示是否回收，必须补充类型化安全阶段／原因结果，不能用一个回收布尔量假定错误正文已保留。诊断通道饱和、断开或最终输出不可写均不触发业务停止、出口提升或控制重试；关键故障仍由原业务状态机处理。输出不可用时不承诺外部日志可见，恢复后按上述固定计数报告损失，不扩大缓冲或回写完整错误链。

停止先阻止新事件、关闭本次写端，接收端排空最多 1 秒，且包含在实例原有十五秒总停止预算内；剩余预算不足时以剩余预算为准，不能另加一秒。到期取消日志交付并回收读者，普通尾部事件按等级计数，关键退出阶段／原因由独立失败结果保存。生产者、排空及最终写入均不得无限阻塞资源回收；不改变 stderr 租约或以“日志已打印”替代退休确认。

正常的等级／频率／五秒摘要保证以接收端和输出目标可用为前提；另有强制拥塞及不可写测试，验证计数、优先级、独立关键错误和总停止预算。不能用输出故障掩盖正常环境中缺失的重要事件。

## 敏感信息与验收适配

可输出安全字段和类型化原因，禁止整体序列化配置、密码、用户名、访问令牌、私钥、原始 URL、完整外部输出或任意错误链。参数和 JSON 解析错误应归一为字段及固定安全说明；不能仅依赖匹配 password 字样的字符串替换。

依赖调试日志的既有测试须显式选择 debug；默认安静测试独立存在。缓存恢复和未选国家候选判断需状态及持久材料的正证据，不能以日志缺失推断某行为未发生。debug 的正对照仍需证明相应事件能真实产生。

运行验证覆盖四等级、1／60／300 秒摘要、十分钟默认安静、来源失败／活动阻断恢复、正常停止与日志通道拥塞；状态查询始终输出原单个 JSON，原退出码保持不变。
