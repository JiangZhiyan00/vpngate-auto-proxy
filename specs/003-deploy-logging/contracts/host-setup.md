# 宿主首次准备契约

对应需-001—需-006、成-001、成-002。安装器是部署材料，与现有 install-vap.py 定位一致，不是新增产品 CLI；不创建 vap 包装器或第二产品名称。

## 交付与信任

同一严格正式版本发布附带：

- `vap-host-init-vX.Y.Z.py`：单文件标准库安装器，内嵌该版本唯一生产策略及摘要、来源提交和项目许可。
- `host-setup.json`：安装器、策略、版本、对应最终镜像与支持范围的绑定清单。
- `host-setup-command.txt`：一条首次准备命令及校验说明，固定官方版本 URL 和安装器预期摘要。
- 原 `SHA256SUMS` 追加新材料摘要，原完整源码及 validation.json 继续公开保留。

生成命令只在 root 私有临时目录获取材料，严格限定 HTTPS、目标官方仓库和版本，限制下载时间与大小；校验安装器摘要后才执行，失败不得运行。不得用移动分支／latest、未经校验的管道执行或任意远端 URL。初始信任是维护者从官方发布说明获取的版本和摘要，同来源 SHA 校验不是独立签名认证。

安装器执行阶段不联网，不从本地源码目录读取策略，不下载或执行额外程序。运行时只调用受保护路径上的宿主既有命令，清理危险环境变量、使用受控 PATH 和明确的子进程参数，不拼接用户命令。

## 参数与退出行为

以下接口已实现并通过隔离测试；真实宿主支持矩阵及正常重启验收仍待完成：

```text
python3 vap-host-init-vX.Y.Z.py
python3 vap-host-init-vX.Y.Z.py --check
python3 vap-host-init-vX.Y.Z.py --adopt
python3 vap-host-init-vX.Y.Z.py --update-from vA.B.C
python3 vap-host-init-vX.Y.Z.py --help
```

| 操作 | 行为 |
| --- | --- |
| 默认 | 首次安装或同版本复核；不自动替换不同版本、不自动接管未知历史材料 |
| --check | 只读核对，不创建锁、目录或登记，不加载策略；缺失或不一致返回未通过 |
| --adopt | 只接管与安装器内嵌官方策略完全相同的现有文件，仍要求受保护元数据、无活跃使用者；不能接管未知字节或仅存在的未知内核策略 |
| --update-from | 必须匹配受保护登记中的旧版本及文件摘要，明确进行版本更新；不允许任意目标路径或无记录更新 |
| --help | 中文说明及支持范围，无需 root、不联网、不创建任何资源 |

写操作互斥；不能组合 check、adopt 和 update。目标新版本固定在安装器中，无 latest 解析或自由 URL／目标路径参数。

退出码：0 全部必要检查通过；1 前提缺失、冲突或操作失败且状态已明确；2 参数错误；4 恢复失败或状态不确定。安装器退出码独立于 vap 运行控制退出码，不修改后者。输出中文逐项结果和最后一条安全结果 JSON；不输出环境、凭据或整个宿主配置。

## 支持和检查

首个支持范围：Debian 12、Ubuntu 24.04、Linux x86_64、systemd 管理的真实宿主、本机有根 Docker。要求实际及有效用户均为 root，Python ≥3.10，AppArmor 启用、securityfs 可读、apparmor_parser 和标准 include 存在、Docker 可查询、隧道设备存在。远端 Docker 上下文、无根引擎、容器内执行、未知发行版或不可确认的宿主命名空间拒绝。

检查系统服务持久启用、未屏蔽、标准启动加载链可用，策略不在 disable／force-complain 中。不自动 enable／restart／reload 系统服务，不修改内核参数、Docker 配置、默认策略、其他策略或用户 Stack。

固定路径：

| 用途 | 路径与约束 |
| --- | --- |
| 生产策略 | /etc/apparmor.d/vpngate-auto-proxy，root:root 0644，普通独立文件 |
| 登记和恢复 | /var/lib/vap-host，root:root 0700；文件 0600 |
| 独占锁 | /run/lock/vap-host-init.lock，项目所有，拒绝链接或错误身份 |

逐段验证父路径、所有权和危险写权限，持有目录描述符并在提交前复核身份；允许工具自身安全的系统链接解析，但未知或可写链拒绝。内嵌策略必须解析成功且只定义精确的 vpngate-auto-proxy 策略。

## 状态、更新与恢复

1. 在修改前完成支持范围、路径、材料和旧状态检查，写操作取得非阻塞项目独占锁；并发冲突返回明确错误。
2. 默认只安装全新状态或复核同版本受管状态。已有相同官方文件但无登记时提示显式 adopt；未知文件、链接、摘要不符或只有未知内核策略全部拒绝。
3. 已管理、同字节且 enforce 正确时不 reload，重复调用不操作活动实例。需要真实加载／替换时，核对宿主所有同名策略消费者均已退出；读不到完整证据则拒绝。安装器不会停止使用者。
4. 在保护目录保存旧材料及事务意图；先核对可恢复性，再提交文件、跳过旧缓存读取加载唯一策略、核对 enforce，最终登记完成。文件与内核不是一个原子事务，不得省略失败恢复。
5. 更新须显式绑定登记旧版本，保护本地修改；策略字节相同可只更新版本登记，无须 reload。任何不同字节更新或接管后的替换仍受无消费者门槛约束。
6. 失败恢复旧文件及登记，内核恢复只能使用已核验旧材料。首次创建且已确认属于本事务、没有使用者的策略可清理；未知或在用策略不卸载。恢复状态不确定则退出 4，并保留登记的恢复材料及具体恢复说明。
7. 下次遇到未完成事务，先核对并恢复该事务或明确拒绝，不将残留当作正常新安装继续覆盖。

成功要求磁盘材料正确、内核精确策略 enforce、持久启动条件满足三者同时成立；普通准备不能声称实际重启已经验证。完整结果字段见 [数据模型](../data-model.md)。

## 发布关联与验收

打包器及策略加入构建输入冻结范围，清单和最终镜像记录同一策略 SHA256。发布镜像增加 `io.vpngate-auto-proxy.apparmor-sha256` 标签，值与公开清单相同。安装器对应源码进入完整来源归档，新附件在镜像推送之前公开；不覆盖历史公开附件或移动旧标签。

普通单元测试使用隔离路径和注入宿主命令，禁止自动触及真实 /etc 或 kernel。两种目标宿主必须分别验证首次、三次重复、不同版本及本地修改冲突、加载失败恢复、活跃消费者拒绝更新、三次代理操作、一次正常宿主重启。宿主重启由维护者在允许中断的目标测试环境执行，不自动重启当前多服务服务器。
